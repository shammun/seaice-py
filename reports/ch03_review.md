## Must-fix

1. **`seaice/core/threshold.py:390` (`_sigma_b2_exhaustive_n3`) and `:518-520` (`multithresh` fallback) — the N = 3 search excludes `t1 = 0` and, when that makes every candidate NaN, the fallback returns N + 1 thresholds.**
   `for i in range(2, nb - 2)` starts at 1-based bin 2, i.e. `t1 >= 1`. The N = 1 branch (`otsuthresh` loops `k = 1..255`, t = 0 included), the N = 2 matrix (`pix_nan = R >= C` allows R = 1, i.e. `t1 = 0`) and MATLAB itself all allow `t = 0`; the book's "0 < t" in Eqs. (3.21)/(3.27) is the same wording for all N, so the N = 3 branch is inconsistent with the port's own N ≤ 2 branches and with MATLAB's convention. Concrete failure (reviewer-run): `A = np.tile(np.array([0, 1, 128, 255], np.uint8), 100)` (darkest level isolated, four non-empty classes need `t1 = 0`) -> every `val` is NaN, `valid = False`, the code falls through to `_degenerate_thresholds(np.unique(A), 3)` whose `need1 <= 0` branch returns `u.copy()` -> **`thresh = [0, 1, 128, 255]` (four values for N = 3) with `metric = 0.0`**, and `imquantize(A, thresh)` would produce five classes. The true exhaustive optimum is `[0, 64, 191]` with metric exactly 1 (computed with the same loop started at bin 1). MATLAB returns `[64 128 191]` / `-Inf` on this input (its `fminsearch` failure mode, same as the `Four` case in the report), so this is not a parity case, but the docstring's "maximised **exhaustively**" and the `(N,)` return contract are both violated.
   Fix: (a) `range(1, nb - 2)` so `t1 = 0` is a candidate; (b) never let the fallback return more than N values — MATLAB only takes `getDegenerateThresholds` when `numel(unique(A)) <= N`, so guard `uniq.size > N` (raise, or return the best finite split) and fix the warning text ("only {uniq.size} distinct values" is false when `uniq.size > N`). Measured effect on the existing references after (a): `Ramp` 66/127/188 and `Rnd` 59/124/190 unchanged; `Four` becomes **34/104/194** (the `t1` plateau tie-average now includes 0; `reports/ch03_verification.md:70` prints 35) — metric still 1.0, `test_multithresh_n3_reimplemented` still passes. Add to `TestL1Otsu.test_multithresh_synthetic`: the four-spike image above -> `thresh.shape == (3,)`, `thresh.tolist() == [0, 64, 191]`, `metric == pytest.approx(1.0)`; and `len(thresh) == N` asserted in every degenerate case.
