## 1. Sections and concepts

### 2.0 Chapter opening (p. 11)
- Digital image = M×N matrix `f(x,y)`, x = row 1..M, y = col 1..N (book uses **x = row, y = column**, i.e. MATLAB `I(x,y)`).
- **Eq (2.1)** matrix representation of an image `f = [f(x,y)]`, 1 ≤ x ≤ M, 1 ≤ y ≤ N.
- Only concept; Python: `np.ndarray` of shape `(M, N)` — no code.

### 2.1 Image types (pp. 11–16)
- 2.1.1 Grayscale: B-bit integers in [0, 2^B−1]; B = 1 gives a binary (logical) image. Fig 2.1 (11×11 block of gray values
  194–207, p. 12), Fig 2.2 (16×16 binary pattern, p. 12).
- 2.1.2.1 RGB: image is M×N×3. **Eq (2.2)** `C(x,y) = [R(x,y); G(x,y); B(x,y)]`. Fig 2.3 (p. 14) shows the three channels of
  `rgb.JPG` and quotes **R(1076,675)=28, G(1076,675)=76, B(1076,675)=114** (verified exactly against `data/book/ch02/rgb.JPG`
  with `imageio`: `I[1075,674] = [28, 76, 114]`).
- 2.1.2.2 CMY/CMYK: **Eq (2.3)** `[C;M;Y] = [1;1;1] − [R;G;B]` with RGB normalised to [0,1] (on uint8 this is
  `imcomplement` = 255 − I). **Eq (2.4)** `[C;M;Y;K] = [1;1;1;0] − [R;G;B;0] − Kb·[u;u;u;−b]`,
  **Eq (2.5)** `Kb = min(1−R, 1−G, 1−B)`; u = under-colour-removal factor, b = darkness factor, both in [0,1].
  Fig 2.4 (p. 14): C, M, Y component images. No CMYK code in MATLAB folder.
- 2.1.2.3 HSI: **Eq (2.6a)** `[I;V1;V2] = [[1/3,1/3,1/3]; [−1/√6, −1/√6, 2/√6]; [1/√6, −1/√6, 0]]·[R;G;B]`,
  **Eq (2.6b)** `H = arctan(V2/V1)`, **Eq (2.6c)** `S = sqrt(V1² + V2²)`. Fig 2.5 (p. 15): H, S, I component images.
- 2.1.3 Indexed image: integer matrix + m×3 colormap (rows in [0,1]); Fig 2.6 (p. 16) is a structure diagram. No code.

### 2.2 Image histogram (pp. 16–17)
- **Eq (2.7)** `h(r_k) = n_k` — number of pixels at intensity level r_k, k = 0..L−1, L = 2^B.
- **Eq (2.8)** `p(r_k) = h(r_k)/n = n_k/(M·N)` — normalised histogram = probability of level r_k.
- Fig 2.7 (p. 17): an 8-bit grayscale image (a dense floe field — **not** `rgb.JPG`, see §5) and its `imhist` bar plot
  (peak ≈ 7.2×10⁴ near level 195). Fig 2.8 (p. 17): `rgb.JPG` and its three channel histograms (Red solid, Green dashed,
  Blue dotted; y-limit 8×10⁴). Histograms motivate thresholding in §3.1.

### 2.3 Basic relationships between pixels (pp. 17–20)
- 2.3.1 Neighbourhoods: N4(p) = {(x±1,y),(x,y±1)} (distance 1); ND(p) = four diagonals (distance √2); N8 = N4 ∪ ND.
  Border pixels have neighbours outside the image. Fig 2.9 (p. 18).
- 2.3.2 Adjacency w.r.t. intensity set V: 4-adjacent (q∈N4(p)), 8-adjacent (q∈N8(p)), m-adjacent (q∈N4(p), or q∈ND(p)
  and N4(p)∩N4(q) contains no V-valued pixel). m-adjacency removes 8-path ambiguity.
- 2.3.3 Path: sequence p1..pn with consecutive pixels adjacent; length n; closed if p1 = pn. Fig 2.10 (p. 19): 4-, 8-, m-paths
  on a 3×3 example.
- 2.3.4 Connectivity / connected components; Fig 2.11 (p. 20): the same 10×13 binary matrix has **5 components with
  4-adjacency and 2 with 8-adjacency** (matrix decoded below; use it as a test fixture).
- 2.3.5 Region = connected set; adjacent/disjoint regions; **boundary of R** = pixels of R with ≥1 neighbour outside R;
  boundary of a finite region is a closed path.
- No numbered equations; no MATLAB code. Implement neighbour sets / labelling wrappers (`bwlabel`-compatible).

### 2.4 Distance transform (pp. 20–23)
- **Eq (2.9)** `D(p) = 0 if p∈B (background); min_{q∈B} d(p,q) if p∈O (object)` — distance of every object pixel to the
  nearest background pixel. Metric axioms: positive definite, symmetric, triangle inequality.
- **Eq (2.10)** Euclidean `d_e = sqrt((x−u)² + (y−v)²)` — iso-distance set is a circle.
- **Eq (2.11)** City-block `d_4 = |x−u| + |y−v|` — diamond; r = 1 set = N4.
- **Eq (2.12)** Chessboard `d_8 = max(|x−u|, |y−v|)` — square; r = 1 set = N8.
- 2.4.4 Performance: Euclidean accurate but slow (sqrt/float); d4/d8 fast, less accurate.
- Fig 2.12 (p. 21): 7×7 binary matrix (a) and its Euclidean DT (b) — values 0/1/1.4142/2/2.2361 (fixture below).
  Fig 2.13 (p. 22): city-block (max 6 at corners) and chessboard (max 3) distances from the centre of a 7×7 grid.
  Fig 2.14 (p. 23): 201×201 image with one centre pixel; Euclidean / city-block / chessboard maps (= `distance_transform.m`).
- **Semantics note**: MATLAB `bwdist(BW)` = distance to the nearest *nonzero* pixel, so Eq (2.9) = `bwdist(~f)`; scipy
  `distance_transform_edt(f)` computes distance of nonzero pixels to the nearest zero = Eq (2.9) directly.

### 2.5 Convolution (pp. 22–24)
- **Eq (2.13)** continuous 2-D convolution `h = ω∗f = ∬ ω(u,v) f(x−u, y−v) du dv`.
- **Eq (2.14)** discrete convolution with an m×n kernel: `h(x,y) = Σ_{s=−m/2}^{m/2} Σ_{t=−n/2}^{n/2} ω(s,t) f(x−s, y−t)`.
- **Eq (2.15)** explicit 3×3 expansion (nine ω(s,t)·f(x−s,y−t) terms). Fig 2.15 (p. 24) diagram of a 3×3 kernel response.
- Odd-sized kernels preferred (unique centre). Note (2.14)/(2.15) are *true convolution* (kernel flipped); MATLAB `imfilter`
  defaults to correlation — relevant for Ch4/Ch5/Ch6 (`imfilter`, `xconv2`). No MATLAB code in ch2.

### 2.6 Set and logical operations (pp. 24–29)
- 2.6.1 Binary images as sets: **Eq (2.16)** `G = {(x,y) | g(x,y) = 1}`; **(2.17)** `ω ∈ A`; **(2.18)** `ω ∉ A`;
  **(2.19)** `A ⊆ B`; **(2.20)** `B = {ω | condition}`; universe U = image rectangle;
  **(2.21)** complement `Aᶜ = {ω | ω ∉ A} = U − A` (swap 0/1); **(2.22)** union `A ∪ B` (OR); **(2.23)** intersection
  `A ∩ B` (AND); **(2.24)** difference `A − B = A ∩ Bᶜ`; Fig 2.16 (p. 26) shows A, B, Aᶜ, A∪B, A∩B, A−B on 16×16 grids.
- **(2.25)** reflection `Â = {ω | ω = −a, a ∈ A}` (180° rotation about the set origin); **(2.26)** translation
  `(A)_z = {c | c = a + z, a ∈ A}`. Fig 2.17 (p. 27) — used by morphology in §4.2.
- 2.6.2 Grayscale images as 3-D sets: **(2.27)** `G = {(x,y,z) | z = g(x,y)}`; **(2.28)** complement `Aᶜ = {(x,y,L−z)}`,
  L = 2^k − 1; **(2.29)** union = pixelwise max; **(2.30)** intersection = pixelwise min.
- 2.6.3 Logical NOT/OR/AND (Table 2.1, p. 28); for grayscale, bitwise: **57 AND 207 = 9** (p. 29, 00111001 & 11001111 = 00001001).
- No MATLAB code; trivial numpy (`~`, `|`, `&`, `np.maximum`, `np.minimum`, `L − I`, `np.bitwise_and`).

### 2.7 Chain code (pp. 29–31)
- Freeman chain code: boundary as a sequence of direction numbers, 4-direction (0..3) or 8-direction (0..7, multiples
  of 45°; even = horizontal/vertical, odd = diagonal). Fig 2.18 (p. 29) numbering; Fig 2.19 (p. 30): 8×9 binary object
  with its 4-direction (22 codes) and 8-direction (18 codes) boundary codes.
- Representation = starting coordinates + code list (Fig 2.20, p. 31: 18 coordinates starting at (4,2), code
  `0 1 2 0 0 7 0 6 6 4 5 6 4 4 3 4 2 2`).
- Start-point normalisation: treat code as circular, rotate to the *integer of minimum magnitude*.
- Rotation invariance: **Eq (2.31a)** `D1(i) = (C(i+1) − C(i)) mod 8, i = 0..N−2`; **Eq (2.31b)** `D1(N−1) = (C(0) − C(N−1)) mod 8`
  (mod 4 for 4-connected). First difference may itself be normalised (min-magnitude rotation).
- Fig 2.21 (p. 31) values for the Fig 2.19 object: original code `0 1 2 0 0 7 0 6 6 4 5 6 4 4 3 4 2 2`; first
  difference `1 1 6 0 7 1 6 0 6 1 1 6 0 7 1 6 0 6`; normalised code `0 0 7 0 6 6 4 5 6 4 4 3 4 2 2 0 1 2`; its first
  difference `0 7 1 6 0 6 1 1 6 0 7 1 6 0 6 1 1 6`; normalised first difference `0 6 1 1 6 0 7 1 6 0 6 1 1 6 0 7 1 6`.
- Not scale invariant; noise-sensitive. Code: `chain code/` folder (Gonzalez–Woods–Eddins DIPUM functions).

### 2.8 Image interpolation (pp. 32–36)
- **Eq (2.32)** forward coordinate transform `(η,ξ) = T{(x,y)}`; Fig 2.22 (p. 32).
- 2.8.1 Nearest neighbour: **Eq (2.33)** inverse mapping `(u,v) = T⁻¹{(m,n)}`, take the value of the closest lattice point;
  Fig 2.23 (p. 33). Fast; mosaic/saw-tooth artefacts.
- 2.8.2 Bilinear: **Eq (2.34)** `f(u,v) = Σ_{m,n=0}^{1} a_mn uᵐ vⁿ`; with P1=(i,j), P2=(i,j+1), P3=(i+1,j), P4=(i+1,j+1):
  **(2.35)** `f(Q1) = (j+1−v) f(P1) + (v−j) f(P2)`; **(2.36)** `f(Q2) = (j+1−v) f(P3) + (v−j) f(P4)`;
  **(2.37)** `f(P) = (i+1−u) f(Q1) + (u−i) f(Q2)` (expanded to four area weights);
  **(2.38)** matrix form `f(P) = [i+1−u, u−i] · [[f(P1), f(P2)]; [f(P3), f(P4)]] · [j+1−v; v−j]`. Fig 2.24 (p. 34).
- 2.8.3 Bicubic: **Eq (2.39)** `f(u,v) = Σ_{m,n=0}^{3} a_mn uᵐ vⁿ` (16 coefficients from 4 values + 8 first derivatives +
  4 cross derivatives, Fig 2.25 p. 35); practical form = cubic convolution:
  **(2.40)** `f(u,v) = Σ_{m=−1}^{2} Σ_{n=−1}^{2} f(i+m, j+n) · rc(m + i − u) · rc(−(n + j − v))` (book prints `f(u+m, v+n)`;
  the lattice indices must be `(i+m, j+n)`); **(2.41)** Keys kernel
  `rc(x) = (a+2)|x|³ − (a+3)|x|² + 1 for |x|≤1; a|x|³ − 5a|x|² + 8a|x| − 4a for 1<|x|≤2; 0 otherwise`, a = tuning factor
  (MATLAB `interp2 'cubic'`/`imresize 'bicubic'` use a = −0.5; OpenCV uses −0.75).
- No MATLAB code in ch2; used later by Ch6 `snakedeform.m` (`interp2`) and App. A orthorectification (image warp).

## 7. Risks & questions

1. **`color_image.m` line 21 bug**: `2*Ig` instead of `2*Ib` makes `V2 = −V1` and `Ih ≡ atan(−1) = −π/4` (NaN where R = G);
   book Fig 2.5(a) shows exactly such a flat image. Decision proposed: port Eq (2.6a) as written in the text (authority on
   *what*), keep a `matlab_bug=True` switch only for reproducing the printed figure, and record the deviation with both
   references in the report. Needs the orchestrator's OK.
2. **`atan` vs `atan2`** in Eq (2.6b): the book uses `arctan(V2/V1)` (range ±π/2, undefined when V1 = 0). Port default
   follows the book; expose `use_atan2=True` for a proper hue in [−π, π]. Document.
3. **HSI scaling**: the code works on 0–255 doubles, the text says RGB normalised to [0,1]; H is scale-free, I and S scale
   by 255. Port on [0,1] floats (text), compare with MATLAB after ×255 for I/S.
4. **`minmag` non-termination on periodic codes** (all remaining candidates identical → `z` never assigned → MATLAB error).
   Fig 2.21's "normalised first difference" (period 9) cannot be produced by `fchcode.m`; the port must break ties. Label that
   path `reimplemented` (verified vs the book sequence), not `exact`.
5. **`boundaries.m` double traversal** on shapes with 1-pixel spurs and its *exterior-only* tracing (holes are never traced;
   `isempty(B{label})` guard). These are DIPUM behaviours that ch5 depends on — replicate, do not "fix"; test with the
   spur fixture in `boundaries_multi.mat`.
6. **`bwlabel` numbering**: `boundaries` returns cells in `bwlabel` label order (column-major first occurrence). Python must
   relabel skimage output to that order so that ch5 code indexing `b{k}` stays comparable. `label_agreement` in
   `tools/compare_arrays.py` compares partitions only; add a strict label-number check for this primitive.
7. **Coordinate convention**: MATLAB boundaries/`x0y0`/`bound2im(x0,y0)` are 1-based (row, col). Proposal: Python uses
   0-based (row, col) everywhere and the tests add 1 when comparing; document in the docstrings and in
   `knowledge/function_map.md` so ch5 does not mix conventions.
8. **`'cww'` typo** in `chain_diff.m` (intended `'ccw'`): the effective trace is clockwise and that is what Figs 2.20/2.21
   show. Port keeps clockwise; mention in the script docstring.
9. **`rgb2gray` parity**: MATLAB computes `0.2989 R + 0.5870 G + 0.1140 B` in double then rounds; a few pixels may differ by
   1 from a naive float32 implementation. Use float64 and `np.floor(x + 0.5)`; measure the differing-pixel fraction.
10. **JPEG decoding**: MATLAB and imageio/Pillow both use libjpeg but versions/DCT methods may differ by ±1 level. The
    quoted pixel matched exactly; still compare `I` against `histogram.mat: I` and report the fraction of pixels ≠ 0.
11. **Eq (2.9) vs `bwdist` semantics**: text defines distance *from object to background*; `bwdist` gives distance *to
    nearest nonzero*. `distance_transform.m` intentionally computes `bwdist(point)`. Keep two clearly named functions
    (`distance_transform` = Eq 2.9 = `bwdist(~f)`, `bwdist` = MATLAB semantics). MATLAB returns single precision → compare
    with `atol=1e-4`.
12. **quasi-euclidean** is not used in ch2 but appears in the `bwdist` option list; ch5 `distance_propagation.m` should be
    checked when porting ch5 — implementing it now (two-pass chamfer 1/√2) is cheap and verifiable against MATLAB.
13. **Fig 2.7 source image unknown** (not `rgb.JPG`). Candidate: another chapter's shipped image (see §5). If none matches,
    the report must say Fig 2.7 is illustrated with a substitute.
14. **Eq (2.40) index typo** (`f(u+m, v+n)` should be `f(i+m, j+n)`) and the sign inside the second `rc` (irrelevant, rc is
    even). Implement the standard Keys cubic convolution with a = −0.5 (MATLAB `interp2 'cubic'`/`imresize 'bicubic'`) and
    expose `a` per Eq (2.41). Never claim exact parity with `imresize` (antialiasing, half-pixel centre convention).
15. **Bilinear index convention**: book P1..P4 use x = row index i, y = column index j (consistent with Eq 2.1). Port must
    keep (u = row, v = col) to avoid a transposed result; test against `interp2` with explicit meshgrid.
16. **`histogram.m` side effects**: writes `red.png/green.png/blue.png` (figure screenshots) — the Python script saves
    channel images directly; when generating the MATLAB reference, run from a scratch directory so nothing is written into
    `MATLAB_ROOT`.
17. **No Octave**: the fallback path of `run_ref` is unavailable; all L2 references depend on MATLAB `-batch` working
    headlessly (`set(0,'DefaultFigureVisible','off')` is already in `run_matlab_ref`). `text(...)` and `imshow` in
    `chain_diff.m` should run fine with figures invisible; if not, save `c` fields via explicit statements instead of `run`.
18. **Dependencies on later chapters**: none for ch2 itself, but ch4 (§4.2) relies on `setops.reflect/translate`, ch5 on

### 7.1 Book text issues (found during port/review)

- **Eq. (2.15) is printed in correlation form, inconsistent with Eq. (2.14)** (p. 24, `chapters/ch02.txt` ~1510-1514).
  Eq. (2.14) defines convolution as `h(x,y) = Σ_s Σ_t ω(s,t) f(x−s, y−t)` (kernel flipped, = MATLAB `conv2`), but the
  nine-term expansion of Eq. (2.15) reads `ω(−1,−1) f(x−1,y−1) + ω(−1,0) f(x−1,y) + … + ω(1,1) f(x+1,y+1)`, i.e.
  `Σ ω(s,t) f(x+s, y+t)` — *correlation* (kernel not flipped, = MATLAB `imfilter(f, w)` default). The two agree for
  symmetric kernels and differ in sign for antisymmetric ones (the Sobel-type demo kernel of `convolution_example`
  gives +1 under Eq. 2.14 and −1 under Eq. 2.15 as printed). Decision: `core.filters.conv_at` implements Eq. (2.14) by
  default and offers `correlate=True` for Eq. (2.15) as printed; `fig_2_15_convolution.png` and
  `scripts/ch02_convolution.py` show both values with the correct equation labels. When ch4 cites "convolution" for
  Sobel/Prewitt, check whether the MATLAB code uses `imfilter` (correlation) or `conv2` before labelling parity.
- Eq. (2.40) index typo (`f(u+m, v+n)` for `f(i+m, j+n)`) — see item 14 above.
- `color_image.m` line 21 `2*Ig` vs Eq. (2.6a) `2*Ib` — see item 1 above.
- `chain_diff.m` `'cww'` typo — see item 8 above.
