## 1. Sections and concepts

### 6 Introduction (pp. 109–110)
- A snake = deformable/active contour [75]; internal forces from the curve, external from the image + constraints; it stops where they balance.
- Parametric (Lagrangian, explicit points) vs geometric (level-set, Eulerian) snakes [19–21, 175]. Geometric snakes handle topology changes but "leak out" at weak/gapped boundaries → **the book uses parametric snakes only**, for their weak-edge detection.
- Two classic failures: the **capture range** of the external force field is tiny, and the forces have no component pulling the snake into **boundary concavities**.
- Prior fixes: multiresolution [83], distance potential force [30], balloon force [29] — each solves one problem and creates another.
- **GVF** [174] = a static external force field obtained by diffusing the gradient vectors of an edge map → large capture range + forces that point into concavities.
- The chapter adds an **automatic contour initialization based on the distance transform** so that no user interaction is needed.

### 6.1 Traditional parametric snake model (pp. 110–122)
- **(6.1)** `s = ∫₀ᵗ |dc/dt| dt` — arc length of a parametrised curve `c(t)`; `dc/dt` is the tangent (unit if `t` is arc length).
- Snake = `c(s) = (x(s), y(s))`, `s ∈ [0,1]`, **closed**: `c(0) = c(1)` (Fig. 6.1).
- **(6.2)** `E = ∫₀¹ Eint(c(s)) + Eext(c(s)) ds` — the functional to minimise.

#### 6.1.1.1 Internal energy (pp. 111–113)
- **(6.3)** `Eint = ½α|dc/ds|² + ½β|d²c/ds²|²` — stretching (elastic, weight α) + bending (curvature, weight β).
- α controls point spacing / tension: large α ⇒ evenly spaced points, fewer loops and ripples, shorter snake; α = 0 ⇒ uneven spacing (**Fig. 6.2(a)–(c)**).
- β controls rigidity: large β ⇒ smooth contours; β = 0 ⇒ corners allowed (**Fig. 6.3(a)–(c)**). Setting α or β to 0 at `s` allows a discontinuity there [111, 105].
- Both may vary with `s`; **in this book they are constants** — footnote 2, p. 121: **α = 0.05, β = 0.0 for all snakes unless stated otherwise**.

#### 6.1.1.2 External energy (pp. 113–115)
- **(6.4)** `Eext = Eimage + Econ` — image energy + external constraint energy.
- **(6.5)** `Eimage = γline·Eline + γedge·Eedge + γterm·Eterm`.
- **(6.6)** `Eline = I(x,y)` — sign of γline picks black-on-white vs white-on-black lines.
- **(6.7)** `Eedge = −|∇I(x,y)|²`, gradient angle `θ = arctan(Ix/Iy)`; the minus sign turns "maximise gradient" into "minimise energy".
- **(6.8)** `Eterm = ∂θ/∂n⊥ = (Cyy Cx² − 2Cxy Cx Cy + Cxx Cy²)/(Cx² + Cy²)^{3/2}` — curvature of level contours of the smoothed image `C`; "rarely used" [111].
- **(6.9)** `Eext = γEedge = −γ|∇I|²` — the object-boundary case (line and termination energies set to 0).
- **(6.10)** `C = Gσ * I`, `Gσ = (1/2πσ²)e^{−(x²+y²)/2σ²}` — Gaussian smoothing to enlarge the capture range.
- **(6.11)** `Eext = −γ|∇(Gσ*I)|²` — the smoothed-gradient external energy (**Fig. 6.4(b)**, σ = 5; **Fig. 6.7(b)**, σ = 4).
- **(6.12)** `Eext = −γ I` and **(6.13)** `Eext = −γ Gσ*I` — the binary-image variants [29, 30]. γ must not be 0 (otherwise the snake shrinks to a point).

#### 6.1.2 Implementation (pp. 115–122) — the discretisation `snakedeform.m` implements
- **(6.14)** the total functional written out; **(6.15)** `dE(ĉ+εδc)/dε = 0`; **(6.16)** the perturbed solution; **(6.17)–(6.18)** substitution and expansion of the squares; **(6.19)** Taylor expansion of `Eext`; **(6.20)** `E(ĉ+εδc) = E(ĉ) + ε∫{…}ds + ε∫{…}ds`; **(6.21a/b)** both integrals must vanish.
- **(6.22)** integration by parts; the 1st, 3rd, 4th boundary terms vanish for a closed contour (`δx(1) = δx(0)`); **(6.23)** the reduced integral.
- **(6.24)**, **(6.25)** the **Euler–Lagrange equations** `−d/ds(α dx̂/ds) + d²/ds²(β d²x̂/ds²) + ∂Eext/∂x = 0` (and the `y` twin).
- **(6.26)** `∇E = ∇Eint + ∇Eext = 0`; **(6.27)** force balance `Fint + Fext = 0`; **(6.28)** `Fint = ∂/∂s(α ∂c/∂s) − ∂²/∂s²(β ∂²c/∂s²)`; **(6.29)** `Fext = −∇Eext` (**Fig. 6.4(c)** shows the field; **Fig. 6.5** a converging snake; **Fig. 6.6** a snake that starts too far away and fails).
- **(6.30a/b)** gradient-descent dynamics: `∂x/∂t = −∂/∂s(α ∂x/∂s) + ∂²/∂s²(β ∂²x/∂s²) + ∂Eext/∂x`. *(Sign note: this is `+`(EL residual); Eqs. 6.39–6.40 and `snakedeform.m` implement the descent `−`(EL residual). Port 6.40, flag 6.30.)*
- **(6.31)** `∂c(si)/∂s ≈ (c(si) − c(si−1))/h`; **(6.32)** `∂²c(si)/∂s² ≈ (c(si+1) − 2c(si) + c(si−1))/h²`.
- **(6.33)** the fully discrete EL equation with cyclic indices `s0 = sN`, `s_{−1} = s_{N−1}`; `∂Eext/∂x` at a non-integer location is obtained by **bilinear interpolation** on the image grid (→ `interp2(...,'*linear',0)`).
- **(6.34)** `a_i x(s_{i−2}) + b_i x(s_{i−1}) + c_i x(s_i) + d_i x(s_{i+1}) + e_i x(s_{i+2}) + ∂Eext(s_i)/∂x = 0` with
  `a = β_{i−1}/h⁴`, `b = −2(β_i+β_{i−1})/h⁴ − α_i/h²`, `c = (β_{i+1}+4β_i+β_{i−1})/h⁴ + (α_{i+1}+α_i)/h²`,
  `d = −2(β_{i+1}+β_i)/h⁴ − α_{i+1}/h²`, `e = β_{i+1}/h⁴`.
- **(6.35)**, **(6.36)** the `h = 1` simplification `∂c/∂s ≈ c_i − c_{i−1}`, `∂²c/∂s² ≈ c_{i+1} − 2c_i + c_{i−1}`, giving
  `a = β_{i−1}`, `b = −2(β_i+β_{i−1}) − α_i`, `c = β_{i+1}+4β_i+β_{i−1}+α_{i+1}+α_i`, `d = −2(β_{i+1}+β_i) − α_{i+1}`, `e = β_{i+1}`
  → **exactly `snakedeform.m` lines 29–33** (with the authors' `…m1`/`…p1` names mirrored, see §2 note).
- **(6.37)** `Ax + fx = 0` with the **pentadiagonal circulant** `A` printed on p. 120 (wrap-around entries `a₁,b₁` top-right, `e_{N−1},…` bottom-left); **(6.38)** the `y` twin.
- **(6.39a/b)** implicit-in-`A`, explicit-in-`f` Euler step: `Ax^{t+1} + fx(x^t,y^t) = −λ(x^{t+1} − x^t)`; λ = time step ("viscosity", the code's `gamma`).
- **(6.40a/b)** `x^{t+1} = (A + λI)^{-1}(λx^t − fx)`, `y^{t+1} = (A + λI)^{-1}(λy^t − fy)`. `A + λI` is pentadiagonal and **constant when α, β, λ are constant** → one LU/inverse for the whole evolution, `O(N)`.
- **Fig. 6.5** = the iterative procedure; footnote 2 fixes **α = 0.05, β = 0.0**.

#### 6.1.3 Limitations (pp. 122–123)
- Three properties of `∇f` of an edge map `f`: vectors point to edges (normal on them); large magnitude only near edges; ≈ 0 in homogeneous regions ⇒ **small capture range** (**Fig. 6.6**), and no force into concavities (**Fig. 6.7(a)–(c)**, U-shape, σ = 4).

### 6.2 Gradient vector flow (GVF) snake (pp. 123–128) — what `GVF.m` implements
- **(6.41)** `E = ∬ μ|∇v|² + |∇f|²|v − ∇f|² dx dy = ∬ μ(ux²+uy²+vx²+vy²) + (fx²+fy²)[(u−fx)²+(v−fy)²] dx dy` —
  the GVF energy; μ = regularization parameter; `f` = any edge map (larger on edges). Near edges the 2nd term dominates
  (`v ≈ ∇f`); in homogeneous regions the 1st (smoothing) term dominates → slowly varying field.
  Footnote 3, p. 125: **μ = 0.1 for all GVF snakes in this book**; more noise ⇒ larger μ.
- **(6.42)** perturbed functional `E(û+εp, v̂+εq)`; **(6.43)** the ε-linear form; **(6.44)** `dE/dε = 0`; **(6.45a/b)** both integrals vanish.
- **(6.46)** integration by parts over Ω with boundary ∂Ω; **the natural boundary condition** `∇û·dσ = 0` on ∂Ω
  (→ the mirror boundary condition `BoundMirrorExpand/Ensure` implements exactly this: a zero normal derivative).
- **(6.47)** the reduced integral; **(6.48)** `μ(ûxx+ûyy) − (fx²+fy²)(û−fx) = 0`; **(6.49)** the `v̂` twin.
- **(6.50a/b)** `μ∇²u − (u − fx)(fx²+fy²) = 0`, `μ∇²v − (v − fy)(fx²+fy²) = 0` — in homogeneous regions these are
  **Laplace's equations** ⇒ the field is interpolated from the boundaries and can point into concavities.
- **(6.51a/b)** generalized diffusion equations `∂u/∂t = μ∇²u − (u − fx)(fx²+fy²)` (steady state = the solution).
- **(6.52a–d)** finite differences: `∂u/∂t = (u^{t+1} − u^t)/Δt`; `∇²u = (u(x+1,y)+u(x,y+1)+u(x−1,y)+u(x,y−1)−4u)/ΔxΔy`.
- **(6.53a/b)** the explicit update
  `u^{t+1} = [1 − (fx²+fy²)Δt] u^t + r[5-point Laplacian of u^t] + fx(fx²+fy²)Δt`, and the `v` twin.
- **(6.54)** `r = μΔt/(ΔxΔy)`; **(6.55)** CFL stability `Δt ≤ ΔxΔy/(4μ)` (i.e. `r ≤ ¼`).
  `GVF.m` uses `Δt = Δx = Δy = 1` ⇒ `r = μ = 0.1 ≤ ¼` ✔.
- **(6.56a/b)** the GVF snake evolution: replace `∂Eext/∂x, ∂Eext/∂y` in (6.30a/b) by `−u, −v` ⇒ the update (6.40) with
  `−fx → +κ·u`. **Figs. 6.8, 6.9** show the enlarged capture range and the concavity penetration.

### 6.3 Contours initialization (pp. 128–136)
- A parametric (Lagrangian) snake **cannot split** (**Fig. 6.11**) and cannot segment multiple objects at once [111, 175, 117] ⇒ **one contour per floe, run one by one**.
- **6.3.1 Location** (**Fig. 6.12(a)–(d)**): in the water → the *water* boundary is found; at the floe centre → correct;
  on a weak connection → the connection is found; near the boundary inside the floe → only part of the boundary.
  The curve always stays closed (the enclosed area tends to 0). ⇒ **initialise inside the floe, as close to its centre as possible**.
- **6.3.2 Shape and size** (**Fig. 6.13(a)–(f)**): a **circle** is chosen (it deforms most uniformly to an unknown irregular
  shape); too small a circle needs more iterations and can be trapped by light reflection (6.13(a)–(c)) or speckle
  (6.13(d)–(f)) ⇒ **as close to the actual boundary as possible**.
- **6.3.3 Automatic initialization from the distance transform** (pp. 133–136):
  - Regional/local **maximum** definitions mirroring §5.1 (regional ⇒ local, not conversely [166]).
  - **(6.57)** `Mmax = I − R^D_I(I − 1)` — all regional maxima by grayscale **reconstruction by dilation**.
  - **(6.58)** `Mmax = I + 1 − R^D_{I+1}(I)` — the non-negative-arithmetic equivalent.
  - Distance transform of the binary ice mask; a local maximum in a regional maximum ≈ the object centre; several
    regional maxima per floe are common (**Fig. 6.14**: an 8×8 blob whose city-block DT has one regional maximum made of
    **three** local maxima of value 3).
  - **Dilate** the maxima to merge those within a threshold `T_seed`; the **centre of each dilated region is a "seed"**
    ('+' in Fig. 6.14(b)) and the **radius of the initial circle = the DT value at the seed**, so the circle is strictly
    inside the floe.
  - **Footnote 4, p. 135**: the **city-block** distance is used (moderate number of regional maxima, cf. §5.1.2), so the
    pixel values at the seeds **must be divided by √2** to get the circle radii. → `r = img_Dist(round(cy), round(cx))/√2`.
  - Superimposing all detected boundaries on the binary image separates the connected floes (**Fig. 6.15(f)**); the edge
    pixels are labelled "**residue ice**" for later handling.

### 6.4 Ice image segmentation (pp. 135–137) — **Algorithm 1**
```
1: GVF          ← GVF derived from the grayscale input image
2: SEGMENTATION ← binary ice image
3: D            ← distance map of SEGMENTATION
4: M            ← regional maxima of D
5: S            ← seeds: merge the regional maxima of M within T_seed
6: for each seed s in S:
7:     r ← D(s)                        (÷√2 for city-block, footnote 4)
8:     c ← initial contour = circle at s of radius r
9:     B ← boundary from the GVF snake on c
10:    SEGMENTATION ← SEGMENTATION with B superimposed
11: end for
12: return SEGMENTATION
```
Maxima farther apart than `T_seed` are **not** merged ⇒ a floe may get several seeds; harmless, only slower.
**Fig. 6.15(a)–(f)** is the whole procedure on `alg_seg_gray.jpg`.

**Note (cross-chapter):** the shipped code implements a **superset** of Algorithm 1 — an outer `timer` loop that only
re-segments the components failing three criteria (`Area > Ra`, `Solidity < Rc`, `MajorAxis/MinorAxis > Rl`). Those three
criteria are documented not in ch6 but in **ch9 p. 205** ("1. the ice floe area is less than the given threshold;
2. … ratio between the floe area and its minimum area-bounding polygon area …; 3. the length-to-width ratio of the
minimum area-bounding rectangle …"). Criterion 2 = `Solidity` (convex hull = minimum-area bounding polygon) ✔;
criterion 3 is implemented with the **ellipse axis ratio**, not `minboundrect` — a documented deviation.

### 6.5 Discussion (pp. 137–144)
- **6.5.1 Stopping criterion** — neither [75] nor [174] gives one. Options: cap the iteration count (the code's `iter`), or
  stop when the energy decrease falls below a threshold [124] (risky: the snake can stall in a channel then speed up, cf. Fig. 6.9(a)).
- **6.5.2 GVF capture range** — controlled by the **number of GVF iterations**. **Fig. 6.16**: a **110×186 binary image**
  with a **61-pixel-diameter** large circle and a **9-pixel-diameter** small circle; fields via **5, 30, 100, 250**
  iterations; *5 iterations already fill the 9-px circle*; *30 iterations do not fill the 61-px circle*. **Fig. 6.17**:
  snake evolution on the large circle under **30** vs **250** GVF iterations. Rule of thumb: iterations ∝ object size [61].
  Too large a capture range: strong edges dominate weak ones ⇒ **under-segmentation** (**Fig. 6.18**, 800 vs 80 iterations
  on a model-ice image). Too small: noise blocks the snake ⇒ **over-segmentation** (**Fig. 6.19**, 600 vs 60 iterations).
  A small object near a large one may be mistaken for noise at large capture range.
- **6.5.3 Border effects** — process large images in sub-images, but floes cut by the sub-image border segment badly:
  (a) the snake cannot split and stalls at the border (**Fig. 6.20(a)–(f)**); (b) the GVF field of an incomplete floe
  radiates **from the image border** instead of from the floe centre (**Fig. 6.21(a)–(f)**), and the contour cannot be
  initialised near the cut edges.

### 2.1 `snakedeform.m` in detail (Eqs. 6.36–6.40)

```
alpha = alpha*ones(1,N);  beta = beta*ones(1,N);
alpham1 = [alpha(2:N) alpha(1)];   % NB: this is alpha_{i+1}, not alpha_{i-1}
alphap1 = [alpha(N) alpha(1:N-1)]; % this is alpha_{i-1}
a = betam1;                          %  = beta_{i+1}   (book Eq. 6.36: a_i = beta_{i-1})
b = -alpha - 2*beta - 2*betam1;
c =  alpha + alphap1 + betam1 + 4*beta + betap1;
d = -alphap1 - 2*beta - 2*betap1;
e = betap1;                          %  = beta_{i-1}   (book: e_i = beta_{i+1})
A = diag(a(1:N-2),-2) + diag(a(N-1:N),N-2)
  + diag(b(1:N-1),-1) + diag(b(N),N-1)
  + diag(c)
  + diag(d(1:N-1), 1) + diag(d(N),-(N-1))
  + diag(e(1:N-2), 2) + diag(e(N-1:N),-(N-2));
invAI = inv(A + gamma*diag(ones(1,N)));
for count = 1:ITER
   vfx = interp2(fx,x,y,'*linear',0);
   vfy = interp2(fy,x,y,'*linear',0);
   x = invAI*(gamma*x + kappa*vfx);
   y = invAI*(gamma*y + kappa*vfy);
end
```
- **`a` and `e` are swapped relative to the book's Eq. (6.34)/(6.36) indices** (the authors' `m1`/`p1` names are the mirror
  of the book's). For the **constant** α, β used throughout the book this is immaterial: with constant α, β
  `a = e = β`, `b = d = −α − 4β`, `c = 2α + 6β`, and `A` is symmetric circulant. **With β = 0** (the book's default)
  `A = α·(2I − S − Sᵀ)`, the circulant 1-D Laplacian. Port the code literally *and* expose a book-indexed variant;
  the two differ only for `s`-dependent α, β (never used).
- `inv(A + γI)` is **dense N×N**; the book (p. 121) recommends one LU decomposition. Python: `scipy.linalg.lu_factor`
  once, or the explicit inverse to stay bit-close to MATLAB's `inv` (LAPACK `dgetri`, same as `numpy.linalg.inv`).
- **`interp2(fx, x, y, '*linear', 0)`**: `'*linear'` = bilinear on a uniformly spaced grid; `x` is the **column**
  (horizontal) coordinate, `y` the **row**, both 1-based; the trailing `0` is the **extrapolation value** (not NaN).
  Python: `core.interp.interp2(fx, u=y−1, v=x−1, method='bilinear', fill=0.0)` (`fill` already exists in
  `interp_bilinear`, ch02).
- `N` must be ≥ 3 for the `diag(…, N−2)` terms; `snakeinterp` with `Dmax = 1` always produces `N ≫ 3`.
- With `iter = 100` (or 50) the caller's `for i = 1:ceil(iter/5)` / `if i <= floor(iter/5)` split makes the `else`
  branch **dead code** (it only fires when `iter` is *not* a multiple of 5).

**k-means decision (fn-map row 61).** Use **`core.clustering.kmeans_lloyd(X, k, init='kmeans++', seed=0)`**, *not*
`core.clustering.kmeans_gray(..., shift_bug=True)`. Reasoning:
1. `ch6/` (and `ch7/`, `ch9/Model_Ice_Floe_Identification/`) ship **no `kmeans.m`**, so the call resolves to the
   **Statistics Toolbox** function — a Lloyd/k-means++ algorithm on the raw pixel vector `double(I(:))`, not the
   histogram-based, equal-division-initialised, unit-shifted routine the authors wrote for ch3. Substituting
   `kmeans_gray` would be a silent algorithm change (CLAUDE.md rule 4).
2. R2025a defaults verified in `stats/stats/kmeans.m` line 165: `{'sqeuclidean' 'plus' [] 'singleton' 'off' …}` →
   `Distance 'sqeuclidean'`, `Start 'plus'`, `Replicates 1`, `MaxIter 100`. `kmeans_lloyd(init='kmeans++')` is the same
   algorithm; only the RNG stream differs.
3. The data are **1-D** (409 k grayscale values, ≤ 256 distinct) with `k = 3`, so the objective has an essentially unique
   global optimum. The verifier must therefore compare **sorted cluster centres** (expect ≤ 1e-6 after both converge)
   and **pixel agreement of `bk`** (expect ≥ 99.9 %), and additionally cross-check against a deterministic 1-D optimum
   (exhaustive DP over the 256-bin histogram) to prove the optimum is unique on the book images. Label parity is
   `approx`; `bk` parity should come out `near`/`exact` in practice. Expose `kmeans_impl=` so a MATLAB-seeded run
   (`rng(0); kmeans(...)`) can be dropped in for the reference.

## 7. Risks / open questions (ranked, with proposed resolutions)

**R1 — `polybool` (Mapping Toolbox, compiled GPC `gpcmex`) has no readable source and reorders/reverses vertices.**
Probe: a circle inside the rectangle comes back with all 126 vertices but **rotated start and reversed orientation**
(+ a closing vertex); a clipped circle comes back with 50 vertices including the inserted rectangle corner.
*Resolution*: implement `core.polygon.clip_polygon_rect` as **Sutherland–Hodgman** against the four half-planes
(exact for a convex clip region), then (a) compare **vertex sets** (sorted, `atol=1e-9`) and the **rasterised mask**,
never the order; (b) assert that the snake result is invariant under rotation/reversal of the start point — `snake_matrix`
is circulant and `snakeinterp`'s metric is cyclic, so it provably is, but pin it with a test that runs the same contour
rotated by `k` and reversed. Parity label `reimplemented`. Fall back to `shapely` only as a cross-check, never in the port.

**R2 — `regionprops` `Solidity` / `MajorAxisLength` / `MinorAxisLength` / `Perimeter` / `Orientation` cannot come from
skimage.** Measured on one 12×14 fixture: Major 10.2935 vs 10.3581, Minor 6.6672 vs 6.7664, Perimeter 26.8284 vs

(`uxx = Σx²/N + 1/12`, `uyy = Σy²/N + 1/12`, `y` negated, `2√2·√(uxx+uyy±common)`, orientation in degrees via

## 8. Porter notes (added during the PORT phase, 2026-09-09)

Everything in §3/§4 was implemented as prescribed.  The points below record where the port had to *add* something
the analysis did not specify, or where a measurement changed a proposed default.  No row of the port plan was
overridden.

1. **`snakedeform`'s dense `inv` is unusable at ch6 scale (R4c, measured).** `GVF_distance` on
   `alg_seg_gray.jpg` (201x202) grows its snakes to **N = 1543 points**, and MATLAB's literal
   `invAI = inv(A + gamma*eye(N))` is recomputed after every `snakeinterp`.  Measured wall clock of the whole
   function with the dense inverse: **306 s** (the inverse alone was 3.9 s of the 5.2 s spent on one seed).
   R4(c)'s fast path was therefore implemented and made the **default for N >= 32**
   (`core.snake.CIRCULANT_MIN_N`): with constant alpha, beta, `A + gamma*I` is a *symmetric circulant* matrix
   (`core.snake.snake_first_column`, asserted identical to `snake_matrix` for N = 3..126 and four (alpha, beta)
   pairs), so the system is solved by FFT in O(N log N).  Same function, same result to 8e-12; wall clock
   **2.1 s** instead of 306 s.  `solver='dense'` is kept for the parity test.  Consequence to check in the
   report: `xx = ceil(x)` is discontinuous, so a 1e-12 perturbation moved **1 of 1223** burnt pixels
   (1222 dense vs 1223 circulant).
2. **R4(d) turned out to be unnecessary.** With (1) in place `sea_ice_demo.m` runs at the book's own resolution:
   `seaice_kmean_GVF_forenhancement` on the full 1038x394 `sea_ice_test.jpg` (GVF 500 iterations = 22 s,
   `regionprops` over 231 components = 0.4 s, 598 + 12 snakes) takes **48 s** end to end.  `scripts/
   ch06_sea_ice_demo.py` therefore keeps `sea_ice_test.jpg` as its default image and offers `--downscale` /
   `--max-seeds` only as guards, rather than defaulting to `alg_seg_gray.jpg` as R4(d) proposed.
3. **R7 measured.** `bw_kmeans - bw` has **0** pixels at -1 on `sea_ice_test.jpg` (19 369 at +1), so the
   `bwareaopen` quirk is latent there.  It is reproduced anyway and `strict_bwareaopen=True` /
   `KmeanGVF.n_negative` expose it.
4. **`poly2mask` has a readable codegen twin.** `regionprops`'s `ConvexImage` -> `ConvexArea` -> `Solidity` chain
   needs `roipoly`, whose builtin `poly2mask` has an `eml/poly2mask.m` twin (5x sub-pixel snapping, `intLine`
