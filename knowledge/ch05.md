## 1. Concepts (what the chapter teaches, in our words)

- A gray image is read as a **topographic surface** (Fig. 5.1): water poured on it collects in the **catchment basins**
  of the **regional minima**; the ridges between basins are the **watershed lines**. A regional minimum is a connected
  iso-intensity set whose every neighbour is strictly higher; a local minimum is one pixel ≤ its neighbours (regional ⇒
  local, not conversely).
- Immersion formulation: threshold set `T_h(I) = {(u,v) | I(u,v) < h}` (5.1); regional minima at level h = components of
  `T_h` not touching `T_{h−1}`; **all** minima at once by grayscale reconstruction by erosion `M = R^E_I(I + 1) − I` (5.2,
  Eqs. 4.35–4.38 from ch4).
- Basin recursion: `C_h(M_i) = C(M_i) ∩ T_h(I)` (5.3), `C[h] = ∪_i C_h(M_i)` (5.4), `C[hmax+1] = ∪_i C(M_i)` (5.5),
  `C[h−1] ⊆ C[h] ⊆ T_h(I)` (5.6–5.8). For each component `S` of `T_h`: no basin inside → new minimum; one → grow; several
  → grow each inside `S` by constrained 3×3 dilation and build a 1-px **dam** where they would meet (Fig. 5.4).
- Connectivity duality (pp. 88–89): 8-connected watershed → 8-connected basins, **4-connected** 1-px lines (and vice
  versa). This is what makes `bwlabel(f, 4)` the right call for junction lines in §5.2.
- The gray image is rarely a good **segmentation function** (160 basins on `q.jpg`); the **Sobel gradient** gives 350
  basins (Fig. 5.5), a 7×7 square close-opening of it still 12 (Fig. 5.6); gradients fail entirely when the junction
  between floes is invisible (Fig. 5.7).
- **Distance-transform watershed** (§5.1.2): binarise, take `−bwdist(~bw, metric)` ("inverse distance map"); its
  regional minima = the regional maxima of the distance map, one per convex blob; the ridge crosses the neck between
  touching floes (Fig. 5.8). Metric matters: **Euclidean** → circular propagation → many small "islands" between
  objects (6 basins on `q.jpg`), **city-block** (diamond) moderate (4 minima / 18 px), **chessboard** (square) least
  over-segmentation but under-segments when a long stretch of boundary touches (2 basins) (Figs. 5.9–5.11).
- **Marker-controlled watershed** (§5.1.3): minima imposition = Step 1 `(g + 1) ∧ f`, Step 2 `g' = R^E_{(g+1)∧f}(f)` with
  `f` = 0 on markers, +∞ elsewhere (MATLAB `imimposemin` uses ±Inf and `h = 0.001·range` / 1 instead of the literal +1).
  Worked example (Fig. 5.12): the 4 city-block minima dilated by a **5-radius disk** merge into **2** marker components
  → 2 basins → the two floes separated correctly. Marker design is the hard, image-specific part.
- **Neighbouring-region merging** (§5.2, Zhang/Skjetne/Su POAC 2013, Fig. 5.13): assume convex floes, so a *true*
  junction line has ≥ 1 **concave** ending point. Step 1 Otsu/k-means mask; Step 2 city-block inverse distance map →
  8-conn watershed (over-segmented, Fig. 5.14(e)); Step 3 junction lines `f = bw AND ridges`; Step 4 ending points by
  the kernel `[0 −1 0; −1 4 −1; 0 −1 0]` (response 3 at an end, 4 for an isolated pixel, Fig. 5.15); Step 5 delete every
  line whose two ending points are both convex and merge the two regions (Fig. 5.14(g)–(i)).
- Concavity by the **differential chain code** (§5.2.1): trace the boundary clockwise (Moore tracing with Jacob's
  stopping rule, Fig. 5.16 = DIPUM `boundaries.m`), Freeman code `C`; relative code `R(i) = [C(i) − C(i−1) + 8] mod 8`,
  `R > 4 → R − 8` (5.9); absolute `A(0) = 0`, `A(i) = A(i−1) + R(i)` (5.10), `A(0) − A(N) = 8` for one clockwise turn
  (5.11); absolute sum `S(i) = A(i) + A(i−1) + A(i−2)` with wrap corrections `+16`, `+8` (5.12–5.14), `S(0) − S(N) = 24`
  (5.15); differential `D(i) = S(i+3) − S(i)` (5.16), wrap terms `S(3−j) − 24 − S(N−j)` (5.17–5.18); turning angle
  `θ = 15°·D(i)` (5.19); concave iff **`3 ≤ D(i) ≤ 10`** (45°–150°). Fig. 5.17: the two notches of `q.jpg`.
- §5.3 results (Ny-Ålesund May 2011, brash removed **manually**): Table 5.1 — manual 5/12/20/38 floes; watershed
  12/16/25/60 (over 7/5/7/26, under 0/1/2/5); after merging 5/11/17/37 (over 0/0/0/4, under 0/1/3/6). Remaining errors:
  a concave floe corner is not a junction, a misplaced line with one concave end survives, under-segmentation is not
  fixable. The DT discards the real junction information, so the method suits images where junctions are invisible,
  not crowded MIZ scenes.

## 4. MATLAB→Python lessons learned (new pitfalls; each is a row in `function_map.md`)

1. **A compiled builtin with a readable `eml/` codegen twin is portable line by line.** `watershed.m` calls the compiled
   `images.internal.builtins.watershed_meyer`, but `toolbox/images/images/eml/watershed.m` (+ `FifoPriorityQueue.m`,
   `NeighborhoodProcessor.computeParameters`) is plain M-code that reproduced the builtin at 0 px on 27 pre-check cases
   and then on all 74 verifier fixtures + 11 script images. Look for `eml/<name>.m` before reverse-engineering a builtin
   (ch04's `computeEdges` had no twin).
2. **`FifoPriorityQueue` ≡ `heapq` on `(priority, insertion order)`** — its sift rules are exactly lexicographic. What is
   order-sensitive in Meyer's flooding is only the **initial column-major seed scan** (transposing the image changed
   ridges/partitions in 31 of 80 cases; MATLAB matched the column-major port on all of them); the neighbour scan order
   inside the loop is *provably* irrelevant (a pixel's label depends on the *set* of labels around it and same-label
   pushes are consecutive FIFO entries) — 12 random offset permutations × 80 cases gave 0 differences.
3. **Ridge pixels do not propagate** in MATLAB (a popped pixel that sees two labels keeps 0 and pushes nothing); each
   pixel is pushed at most once with priority `max(A(nb), p)`. `skimage.segmentation.watershed(watershed_line=True)`
   seeds with the minima pixels, re-pushes, tags entries with a source label, keeps propagating from line pixels and
   orders neighbours by distance then row-major → 46–122 differing ridge px on `q.jpg` and *inconsistent basin
   partitions* → `approx` only, unusable for `main.m` (whose junction lines are those ridges).
4. **`watershed` classes**: MATLAB rejects int16/int32 input (`uint8/uint16/single/double/logical` only) — int16 fixtures
   were referenced on `double(X)`; output class follows the region count (uint8 ≤ 255, uint16 above: 6772 / 12 036 basins
   measured) → cast to int32 before comparing label *values*. 3×3 connectivity matrices are accepted only as the cross
   or `ones(3)` (MATLAB `limitedConn` error otherwise); N-D input (`conn` 6/18/26) is not ported.
5. **`imregionalmin(I) = imregionalmax(imcomplement(+I))`** = `skimage.morphology.local_minima(I, connectivity, allow_borders=True)`
   on every probe — including border-touching plateaus, ±Inf pixels and all-±Inf images — **except a constant image**,
   where MATLAB returns all-True and skimage all-False: special-case it. NaN is rejected by both (`'nonnan'`).
6. **`imimposemin` must do `I + h` in the input class**: `bwdist` is single, so the float64 port was 4.8e-7 off MATLAB's
   `Dimp`; in float32 it is **bit-identical**. Markers must be genuine `−Inf` (`intmin`) — a finite sentinel changes all
   328 marker px; `h = 0.001·(max − min)` for floats (0.1 if constant), 1 for integers; on ±Inf images `h = Inf` and
   `−Inf + Inf = NaN` is what MATLAB computes too (`min(NaN, fm)` picks `fm`) → run under `np.errstate(invalid='ignore')`.
   MATLAB silently accepts NaN here (no `'nonnan'`); the port raises. skimage `reconstruction` tolerates ±Inf.
7. **`imreconstruct` with a `{0,1}` marker returns `{0,1}`**, never the label value of the mask component (reconstruction
   by dilation cannot exceed the marker's maximum). `main.m`'s `im = imreconstruct(g, connect)` is therefore a 0/1
   double and `im2bw(im, graythresh(im))` reduces to `im > 0` (review S1 corrected three docstrings claiming `{0, k}`).
8. **`graythresh(RGB)` ≠ `graythresh(rgb2gray(RGB))`**: the RGB call histograms all three planes (130/255 on `q.jpg`) while
   `im2bw` converts to gray; `distance_watershed/marker_watershed/main/chaincode_corner` binarise the RGB (2699 ice px),
   `direct/gradients/topological_surface` the gray image (128/255) — the masks differ. `otsu_mask` takes whatever the
   script passes; state which mask a figure uses.
9. **Keep distance maps in float32** (`bwdist` returns single): Euclidean/quasi maps differ from MATLAB by ~1e-6 in
   float64, and the flooding priorities *and* the regional-minima ties must match bit for bit — `inverse_distance`
   negates the float32 array as is.
10. **Ridge thickness**: on the distance maps the ridges are 4-connected staircases with **0** 2×2 all-ridge blocks (the
    book's "1-pixel-thick 4-connected path", p. 99, holds; a diagonal staircase is expected). On plateau-rich
    segmentation functions Meyer's flooding leaves thick ridges (10 blocks on `watershed(gray)`, 23 on the Sobel map,
    5 on a random uint8 field) — MATLAB identical; do not repeat the 1-px claim for gradient images.
11. **Ending-point rule, text vs script**: the text says response `≥ 3`; `main.m` uses `abs(imfilter(g, wr)) >= max(...)`.
    Same 6 endpoints on `q.jpg` (max = 3 per line) but the literal rule is relative (a closed loop has max 2 → every pixel
    qualifies) and `abs` admits *background* pixels with ≥ 3 line 4-neighbours (16 hits on a 4×4 loop, MATLAB identical).
    Default `'max'` (script), `'ge3'` = the text's signed test (review S2).
12. **`main.m` updates `seg` inside its loop** (later lines see already-merged regions; order = `bwlabel(f, 4)` column-major)
    — `sequential=True` is the script, `False` the text. `freeman_concave` takes **`b{1}`** (first `bwlabel` object; the
    `[max_d, k]` it computes is unused) and errors on boundaries with < 3 codes (`A(l−2)`); single-pixel lines give `T = 4`
    and one ending point (seen on the 552×574 crop).
13. **Integer/logical class rules met here**: `bitand(logical, logical)` is logical; `logical .* logical` is double;
    `intersect(A, B, 'rows')` returns sorted unique rows (`0×2` when empty); `[p, q] = find(mask)` is column-major.
14. **`regionprops(..., 'Centroid')`** = `(x, y)` = 1-based means of (col, row) per component in `bwlabel` order; the
    authors' one-pixel markers are at `floor(Centroid)` (`[23.3089 68.3591; 46 50]` → `[23 68; 46 50]`).
15. **Test design — convex blobs cannot exercise line removal**: a convex blob's distance transform has a single regional
    minimum, so the "spurious lines are removed" test was vacuous (`all([])`, review M1). Use a **peanut** (two r = 20
    discs centred (35,42)/(35,48) on 70×90 → 2 basins, 1 line, 0 concave ends, removed, floes 2 → 1). Also pin the
    default connectivity with a fixture that differs between 4 and 8 (`[[1,5,5],[5,1,5],[5,5,5]]` → 1 vs 2 basins).
16. **Display-only differences that look like bugs**: `label2rgb('shuffle')` permutes with a private fixed-seed stream
    (deterministic in MATLAB, not reproducible); `imshow(I, [])` PNGs differ by 1 level at exact half-integers of the
    `mat2gray` stretch (6 of 55 pairs); `imshow` of a `−Inf` map needs a finite-min convention on both sides.
17. **The authors' `.fig` is a MAT v5 file** (`hgS_070000`): `openfig(..., 'invisible')` in the reference run (or
    `scipy.io.loadmat(struct_as_record=False)`) yields the image `CData` and line series — a free L3 truth (Fig. 5.14(f)
    matched `f` 0 px and the 6 endpoints). R2025a no longer re-creates the old text objects.
18. **DIPUM `boundaries` starts at the first object pixel in column-major order**, so the book's Fig. 5.16 sequence
    `(2,3) → (2,4) → (3,5)` appears as a contiguous sub-sequence of a trace starting at `(3,2)`; `'cww'` (typo) =
    anything-but-`'ccw'` = clockwise, confirmed again against MATLAB.
19. **Performance**: the pure-Python `heapq` flood costs ≈ 3 s per Mpx (fine for 96×81 and the 552×574 crop; a 12-Mpx
    ch7–ch9 frame would take ~40 s per call). See §8.

## 7. Feeds forward — what later chapters will need from this one

- **ch6 (GVF snake, §6.3 automatic contour initialisation)** — the snake is initialised from the ch5 segmentation:
  the separated floe masks (`neighboring_region_merging(bw).seg`, `marker_watershed(bw).seg_ao`,
  `distance_watershed(bw, metric).seg_ao`) and/or the distance-transform minima (`imregionalmin(inverse_distance(bw))`,
  `imregionalmax(bwdist(~bw))`, dilated by `strel('disk', r)` as in Fig. 5.12(b)); per-floe boundaries via
  `label_components` + `core.chaincode.boundaries` (closed, clockwise, 0-based) or `component_centroids` for seed
  points. Check the authors' `GVF*.m`/`snake*.m` for which of these they actually call (`bwdist`, `imregionalmax`,
  `watershed`, `imdilate`, `bwlabel`) and whether the distance map is single. Everything above is 0-px comparable
  against MATLAB; keep distance maps float32 (lesson 9).
- **ch7 (ice types, shape enhancement, `Sea_Ice_Floe_Identification`)** — `core.watershed.watershed`, `imregionalmax` on
  distance maps for floe centres, `imimposemin` for marker control, `neighboring_region_merging` as the floe-separation
  step before classification (its assumptions: convex floes, junction-free binarisation, brash removed first), `bwareaopen`
  for cleaning, `label2rgb` for label displays. Hole filling (§7.1.3) is *not yet in core* — build `imfill` on
  `imreconstruct`/`reconstruct_by_erosion` (border seed), verify like `imimposemin`.
- **ch8 (floe size distribution, ice concentration)** and **ch9 (model-ice floes)** — separated floe masks → per-floe
  areas/perimeters; `watershed` + `bwdist` on rectangular tank floes; `component_centroids`; `regionprops` compat will
  be needed beyond `Centroid` (Area, Perimeter, MajorAxisLength, Orientation — different algorithms from skimage, see
  the skill table) → plan `core.regionprops` verified against MATLAB.
- **Performance thread (open)**: pure-Python heap ≈ 3 s per Mpx → ch7–ch9 full frames (12 Mpx) need a faster engine
  (numba/C++ port of the same loop, or per-level batching) *or* `watershed_skimage` explicitly labelled `approx` for

## 8. Open questions / things to revisit

1. **Figs. 5.7, 5.11, 5.18–5.20 and Table 5.1 `unverified`** (unshipped Ny-Ålesund images). If the user supplies them,
   run `scripts/ch05_experiments.py --image …` (brash must be removed manually first, as the authors did) and close the row.
2. **`watershed` speed** (≈ 3 s per Mpx, pure Python): needed decision before the first 12-Mpx call in ch7–ch9 — faster
   exact engine vs `approx` skimage fallback (see §7). Any faster engine must reproduce the 74 `compat` cases with label
   values, including the 31 order-sensitive ones.
3. **N-D `watershed`** (`conn` 6/18/26) and **`imimposemin` with NaN** (MATLAB accepts, port raises) are documented
   deviations; revisit only if a later chapter needs them.
4. **`regionprops`** is only covered for `'Centroid'`; ch8/ch9 will need Area/Perimeter/axes/Orientation with MATLAB's
   algorithms (skimage's differ) → a verified `core.regionprops` is the next compat primitive after `imfill`.
5. **`watershed_immersion`** (teaching form) places dams differently from Meyer's flooding on shared plateaus
   (partition agreement ≥ 0.75 on the plateau-maximum profile) — fine for teaching, never use it in a pipeline.
6. **Endpoint rule** — the book's `≥ 3` and the script's `>= max` agree on every image seen so far; if a later
   pipeline meets closed-loop junction lines (max = 2) the literal script rule marks every pixel an ending point.
7. **`freeman_concave` fragility** on tiny regions (< 3 codes) and its `b{1}` choice: ch7's pipeline should clean
   speckle (`bwareaopen`) before calling it, or pass `object='longest'` explicitly.
8. Typo/notation records: `'cww'` (clockwise) in `boundaries` calls; the book shows one line removal in Fig. 5.14(g)–(h)
   while the script removes two; Fig. 5.16's trace starts at a different pixel than DIPUM's.
