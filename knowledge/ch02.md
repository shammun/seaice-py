## 1. Concepts (what the chapter teaches, in our words)

- An image is an M×N matrix `f(x, y)` with **`x` = row (1..M), `y` = column (1..N)** — Eq. (2.1). Every coordinate
  convention in the package follows this: `(row, col)`, 0-based in Python.
- Image types (§2.1): B-bit grayscale (B = 1 → binary/logical); RGB `C(x,y) = [R;G;B]` (Eq. 2.2); CMY = 1 − RGB on
  normalised values (Eq. 2.3, = `imcomplement`); CMYK with under-colour removal `u` and darkness `b`,
  `Kb = min(1−R, 1−G, 1−B)` (Eqs. 2.4–2.5); HSI via the fixed 3×3 matrix `[I;V1;V2] = M·[R;G;B]`, `H = atan(V2/V1)`,
  `S = sqrt(V1²+V2²)` (Eqs. 2.6a–c); indexed image = integer matrix + m×3 colormap (§2.1.3).
- Histogram `h(r_k) = n_k` (Eq. 2.7) and normalised histogram `p(r_k) = n_k/(MN)` (Eq. 2.8) — the foundation of the
  thresholding methods of Ch3.
- Pixel relationships (§2.3): N4 / ND / N8 neighbourhoods; 4-, 8- and m-adjacency (m removes 8-path ambiguity); paths;
  connected components (Fig. 2.11: 5 with 4-adjacency, 2 with 8-adjacency); a region's boundary = its pixels with at
  least one neighbour outside the region, and it is a closed path.
- Distance transform, Eq. (2.9): distance of every **object** pixel to the nearest **background** pixel, with Euclidean
  (2.10), city-block (2.11) and chessboard (2.12) metrics (iso-distance sets: circle / diamond / square).
- Convolution, Eq. (2.14): `h(x,y) = Σ_s Σ_t ω(s,t) f(x−s, y−t)` — true convolution (kernel flipped). The printed
  nine-term expansion Eq. (2.15) is in *correlation* form (`f(x+s, y+t)`), inconsistent with (2.14) (§7.1 of the
  analysis); MATLAB `imfilter` = correlation, `conv2` = convolution.
- Set/logical operations on binary images (Eqs. 2.16–2.24: complement, union, intersection, difference), reflection
  `Â = {−a}` (2.25) and translation `(A)_z` (2.26) — the building blocks of morphology in Ch4; grayscale images as 3-D
  sets with complement `L − z` (2.28), union = max (2.29), intersection = min (2.30); bitwise `57 AND 207 = 9`.
- Freeman chain codes (§2.7): 4- or 8-direction boundary encoding (Fig. 2.18: 0 = east, 2 = north, 4 = west, 6 = south);
  start-point normalisation = rotate to the integer of minimum magnitude; rotation invariance via the first difference
  `D1(i) = (C(i+1) − C(i)) mod 8` (Eqs. 2.31a–b); not scale invariant, noise sensitive. Used in Ch5 concavity analysis.
- Interpolation (§2.8): inverse mapping `(u,v) = T⁻¹(m,n)` (2.32–2.33); nearest neighbour; bilinear (2.34–2.38, four
  area weights); bicubic as cubic convolution with the Keys kernel (2.40–2.41, `a = −0.5` in MATLAB). Used by the GVF
  snake (Ch6, `interp2`) and orthorectification (App. A).

## 4. MATLAB→Python lessons learned (new pitfalls; each is a row in `function_map.md`)

1. **Coordinates**: book `x` = row, `y` = col; Python 0-based `(row, col)` everywhere. All `chaincode` outputs are
   0-based; `ChainCode.x0y0_matlab` gives the 1-based pair. Tests compare `b_matlab == b_python + 1`.
2. **`bwdist(BW)` vs Eq. (2.9)** are complements: `bwdist(BW) == distance_transform(~BW)`. MATLAB code (`bwdist` in
   ch5/ch6) → `core.distance.bwdist`; book-equation code → `distance_transform`. MATLAB `bwdist` returns **single**;
   compare with `atol≈1e-4` (Euclidean) / `rtol=1e-5` (quasi-Euclidean, MATLAB's chamfer accumulates 1e-4 error).
3. **`conv2` = convolution, `imfilter` = correlation.** Book Eq. (2.15) as printed is correlation and contradicts
   Eq. (2.14). Values differ in sign for antisymmetric kernels (Sobel/Prewitt in Ch4) — check which call each `.m` uses.
4. **`imfilter(I, h, 'replicate')` positional idiom** (ch4–ch6 everywhere): `core.filters.imfilter` accepts the MATLAB
   strings positionally in any order, so the mechanical port works; do not reorder into `mode` by mistake.
5. **`bwlabel` label numbers are column-major first-occurrence**; `label_components` reproduces them (verified on
   Fig 2.11 and a 6-object real mask), so ch5/ch7 code indexing `b{k}`/`regionprops(k)` by label stays comparable.
6. **DIPUM `boundaries`**: exterior boundaries only (holes never traced), closed lists (first point repeated), single
   pixel → two identical points, 1-px spurs traversed twice, `'ccw'` = reversed list. Replicated, not fixed.
7. **DIPUM `fchcode`/`minmag` errors** (`Output argument "z" not assigned`) on periodic codes and single-pixel objects;
   `min_magnitude` breaks the tie (first candidate = lexicographic minimum) — needed for the book's Fig 2.21 last line.
   Any ch5 `try/catch` around `fchcode` must be ported knowing Python never raises there.
8. **`rgb2gray`**: exact only with the NTSC coefficients `0.298936…/0.587043…/0.114021…` computed in double then
   rounded half away from zero (skimage uses Rec. 709 → wrong). JPEG decode via imageio/Pillow is identical to MATLAB
   `imread` on `rgb.JPG` (0 of 9 437 184 samples differ) — no ±1 tolerance was needed here, but keep it in mind for other files.
9. **`imhist(logical)` → 2 bins** at centres `[0, 1]`; uint8 → 256; `imhist(I, n)` bins by `round(v·(n−1)/top)`;
   floats clipped to [0,1]. `nbins=None` in `imhist` follows this rule.
10. **`uint8(x)` ≠ `im2uint8(x)`**: the cast rounds and saturates values in 0–255 units (`to_uint8_saturating`);
    `im2uint8` multiplies [0,1] floats by 255 first. Canonical mapping: MATLAB `uint8()` → `to_uint8_saturating`,
    MATLAB `im2uint8` → `im2uint8`. numpy `astype(np.uint8)` wraps and truncates — never use it for MATLAB casts.
11. **`imcomplement` canonical** = `core.matlab_compat.imcomplement`; `setops.gray_complement` / `bitwise_not` exist only
    as equation-named forms (Eq. 2.28, §2.6.3) — do not use them for MATLAB ports. Note `imcomplement(double 0–255)`
    gives `1 − I` (negative values), exactly as `color_image.m` does.
12. **`interp2`**: Python `interp2(img, u, v, method)` takes 0-based `(row, col)`; MATLAB `interp2(X, Y, Z, Xq, Yq)` has
    `X` = column → `u = Yq − 1`, `v = Xq − 1`. Nearest ties round half away from zero; `'cubic'` = Keys `a = −0.5` with
    **quadratic** edge extrapolation (`pad='quadratic'` is exact at the borders; `'replicate'` is off by up to 7.9 levels
    within 1 px of the edge). Out-of-range → NaN in both.
13. **`imresize` ≠ `interp2`**: `resize` is exact for nearest/bilinear enlargement (antialias off) but bicubic differs at
    the border (≤ 8 levels, 5.6 % px within 1.25 source px of the edge) and there is no antialiasing when shrinking →
    `approx`. Do not use `resize` where ch9 relies on `imresize` numerically.
14. **HSI Eq. (2.6b) with `atan`**: undefined when `V1 = 0` (1 px of `rgb.JPG` on [0,1] inputs, none at 0–255 scale);
    `use_atan2=True` gives a proper hue. `color_image.m` line 21 has `2*Ig` for `2*Ib` → flat hue `−π/4` (Fig 2.5a).
15. **MATLAB script side effects**: `histogram.m` writes `red.png/green.png/blue.png` via `saveas` into the cwd — run
    references from a scratch dir (`outputs/chNN/verify/scratch`) so nothing lands in MATLAB_ROOT.
16. **`imshow(I)` vs `imshow(I, [])`**: only the display changes; `plotting.imshow_scale(autoscale=True)` reproduces
    `mat2gray`-style stretching; PNG comparisons of float maps show ±1 level differences from float32 `mat2gray` rounding
    in MATLAB (not a port defect).
