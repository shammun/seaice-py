## 1. Concepts (what the chapter teaches, in our words)

- A **snake** is a parametric curve `c(s) = (x(s), y(s))`, `s ∈ [0,1]`, closed (`c(0) = c(1)`), that minimises
  `E = ∫ Eint + Eext ds` (6.2). Parametric (Lagrangian) snakes are chosen over geometric/level-set ones because they do
  not "leak" through weak or gapped floe boundaries — at the price of not being able to **split** (Fig. 6.11), hence one
  contour per floe.
- **Internal energy** `Eint = ½α|dc/ds|² + ½β|d²c/ds²|²` (6.3): α = tension (even point spacing, shorter snake, Fig. 6.2),
  β = rigidity (smoothness vs corners, Fig. 6.3). **Footnote 2, p. 121: α = 0.05, β = 0 for every snake in the book.**
- **External energy** (6.4)–(6.13): `Eimage = γline Eline + γedge Eedge + γterm Eterm` with `Eline = I`,
  `Eedge = −|∇I|²`, `Eterm = ∂θ/∂n⊥`; the working form is `Eext = −γ|∇(Gσ*I)|²` (6.11), the Gaussian `Gσ` (6.10) being
  what buys the capture range; `Eext = −γI` / `−γ Gσ*I` (6.12/6.13) are the binary-image variants.
- **Discretisation** (6.14)–(6.36): Euler–Lagrange (6.24)/(6.25), force balance `Fint + Fext = 0` (6.27)–(6.29),
  gradient descent (6.30), finite differences with `h = 1` giving the 5-band coefficients
  `a = β_{i−1}`, `b = −2(β_i+β_{i−1}) − α_i`, `c = β_{i+1}+4β_i+β_{i−1}+α_{i+1}+α_i`, `d = −2(β_{i+1}+β_i) − α_{i+1}`,
  `e = β_{i+1}` (6.36) — **exactly `snakedeform.m` lines 29–33**.
- The system is the **pentadiagonal circulant** `Ax + fx = 0` (6.37)/(6.38); the semi-implicit step is
  `x^{t+1} = (A + λI)^{-1}(λx^t − fx)` (6.40), so with constant α, β, λ one inverse serves the whole evolution.
- **Limitations** (§6.1.3): `∇f` of an edge map is large only *near* edges ⇒ tiny **capture range** (Fig. 6.6) and no
  force into **concavities** (Fig. 6.7, the U-shape).
- **GVF** (§6.2) replaces `∇f` by the field `v = (u, v)` minimising `E = ∬ μ|∇v|² + |∇f|²|v − ∇f|²` (6.41): near edges
  `v ≈ ∇f`, in flat regions the Laplace equations (6.50) interpolate the field from the boundaries — large capture range
  *and* concavity penetration. **Footnote 3, p. 125: μ = 0.1 for every GVF snake in the book.**
- The Euler–Lagrange equations (6.48)–(6.51) are solved by explicit diffusion (6.52)–(6.53) with the natural boundary
  condition `∇û·dσ = 0` (6.46) — which is exactly what `BoundMirrorExpand/Ensure` implement. CFL: `r = μΔt/(ΔxΔy) ≤ ¼`
  (6.54)/(6.55); `GVF.m` runs at `Δt = Δx = Δy = 1`, so `r = μ = 0.1` ✓.
- **Contour initialisation** (§6.3): location matters (in water → the water boundary is found; at the floe centre →
  correct; Fig. 6.12), and a **circle** as close to the true boundary as possible is the best shape (Fig. 6.13).
- **Automatic initialisation from the distance transform** (§6.3.3): regional maxima of the DT by reconstruction —
  `Mmax = I − R^D_I(I − 1)` (6.57), `Mmax = I + 1 − R^D_{I+1}(I)` (6.58) — dilated to merge maxima within `T_seed`; the
  centre of each dilated region is a **seed** and the DT value there is the radius. **Footnote 4, p. 135: the city-block
  metric is used, so the radius must be divided by √2.** Fig. 6.14: an 8×8 blob whose city-block DT has *one* regional
  maximum made of *three* local maxima of value 3.
- **Algorithm 1** (§6.4, p. 136): GVF field ← gray image; D ← distance map of the binary mask; M ← regional maxima;
  S ← seeds; per seed run a GVF snake from the circle `(s, D(s)/√2)` and burn its boundary into the segmentation.
  Boundary pixels are labelled "residue ice". The shipped code is a **superset**: an outer `timer` loop that
  re-segments only the components failing three criteria (`Area > Ra`, `Solidity < Rc`, `MajorAxis/MinorAxis > Rl`) —
  criteria documented in **ch9 p. 205**, where criterion 3 is the min-area **rectangle** ratio while the code uses the
  **ellipse** axis ratio (a deviation of the authors' own code from their text).
- **Discussion** (§6.5): no principled stopping criterion exists (cap the iterations, or stop on energy decrease);
  the capture range is set by the **number of GVF iterations** (Fig. 6.16: 5 iterations fill a 9-px circle, 30 do not
  fill a 61-px one; Fig. 6.17: the snake stalls at 30 iterations and reaches the boundary at 250); too large a range
  under-segments (Fig. 6.18), too small over-segments (Fig. 6.19); sub-image **border effects** break floes cut by the
  tile edge (Figs. 6.20/6.21).

## 4. MATLAB→Python lessons learned (new pitfalls; each is a row in `function_map.md`)

1. **`single` op `double` promotes to double and rounds to single ONCE.** Settled on `dist.m`'s own **540 radii**
   (`r = img_Dist(...)/sqrt(2)`, `img_Dist` from `bwdist` = single): promote-then-round-once reproduces **540/540**
   bit-exactly, rounding `sqrt(2)` to single first matches only **360/540** (up to 1.91e-6 off) and pure double
   arithmetic only **6/540** (up to 7.67e-7). A naive all-float32 port is 1 ulp wrong. `ceil()` downstream is
   discontinuous, so that 1 ulp moves burnt pixels — this rule cut `GVF_distance`'s residual 4×. General rule for ch7–ch9.
2. **Integer-class arithmetic happens *inside* library functions too.** `GVF.m` line 21–23 normalises
   `f = (f − fmin)/(fmax − fmin)` in the **input's** class: handed a uint8 image (`GradientOn = 0`) MATLAB's edge map has
   only the values **{0, 1}**. The port was provably wrong here until review M1 (`saturate_to_class`); now **0.0** at
   ITER 1/5/30/150 and **0 px** end to end. `gradient2` differences in the input class too. This generalises the ch05
   `imimposemin` "arithmetic in the input class" lesson from a script to a *library* function.
3. **`regionprops` must be reimplemented, not delegated to skimage.** skimage disagrees on `axis_major_length`
   (10.2935 vs 10.3581), `perimeter` (26.83 vs 25.42, +5.5 %) and reports `orientation` +90°, which moves the
   `Rc = 0.9` / `Rl = 2` decision boundaries. The port is **exact to 1.07e-14** across 40 shapes × 10 properties and all
   **344** components of the three real ch6 masks, in both call forms. The specific MATLAB algorithms: `+1/12` in the
   second moments, `y` negated, `atan(num/den)` in degrees; hull from the **mid-edge points** of `bwmorph('perim8')`
   pixels with `convhull(rr, cc)` (that argument order); `ConvexImage` = `roipoly(M, N, c, r)` with the
   `firstRow/firstCol` shift; `Perimeter` = Vossepoel–Smeulders over the 8-connected closed boundary.
4. **`polybool` is compiled GPC (`gpcmex`) with no readable source, and its start vertex is not reproducible.**
   0 of 46 per-seed clips (and none of the 7 fixtures) start at max-y, min-y, max-x, min-x or either lexicographic
   extreme; it also **reverses** the traversal. It returns a **closed** ring, and with `Dmin = 0` the duplicate vertex
   survives `snakeinterp` (independent witness: MATLAB's `for_test.m` reference records `XI0` = 252 points against the
   open ring's 251). Compare **vertex sets** and rasterised masks, never order. Rotating the port's own ring by k (a pure
   re-parameterisation) moves the burnt mask by **56–82 px**, bracketing the 74 px gap on the `GVFOn = 0` branch;
   reversing it moves **0 px** (the snake matrix is symmetric). Realigning to MATLAB's start vertex restores 777 points
   and 1.9e-6 px — the proof that ordering, not geometry, is the residual.
5. **`del2` is not the Laplacian.** It is `∇²/(2·ndims)` (`∇²/4` in 2-D — which is why `GVF.m` writes `mu*4*del2(u)`),
   with **linear extrapolation** of the interior second difference at the borders
   (`g(1) = g(2)(h1+h2)/h2 − g(3)h1/h2`, unit spacing `2g(2) − g(3)`), `n == 3` copies the single interior value,
   `n ≤ 2` gives 0, and it divides by `ndims(f)` even in the 1-D branch. `del2(f, h)` uses `h` for both dimensions,
   `del2(f, hx, hy)` swaps them (`x` is dimension 2). 21 cases 0.0.
6. **Long snakes are numerically unstable in their *point count*.** `snakeinterp` inserts where `d > dmax`, and on a
   500–2800-point contour hundreds of spacings sit at exactly `dmax`: a **1e-13** perturbation changed seed 22 from
   2266 to 2262 points (MATLAB 2256). Element-wise parity of long snakes is unobtainable by any float implementation —
   the honest metrics are the **curve** (Hausdorff ≤ 0.4794 px over 46 seeds) and the **mask** (0.050 %). Short snakes
   stay exact (3 of 46 to ≤ 1.5e-13).
7. **A circulant fast path is worth it and is provably the same system.** With constant α, β the matrix `A + γI` is a
   symmetric circulant, so the FFT solve replaces MATLAB's literal `inv(A + gamma*eye(N))` (which is recomputed after
   *every* `snakeinterp`): **306 s → 2.1 s**, ≤ 8.4e-12 apart, final curve 2.7e-8 px, burnt mask 0 px. Keep the dense
   solver for parity tests; `ceil()` is discontinuous, so a handful of burnt pixels can still move (1 of 1223).
8. **MATLAB rejects things the port accepts — record them as evidence.** `gradient2.m` line 47 divides by a double
   *matrix*, and MATLAB refuses `uint8 ./ double_matrix`, so the `GradientOn = 0` **and** `GVFOn = 0` combination
   **cannot execute in MATLAB at all** (L1-only, documented superset). `minboundrect.m` as shipped does not run in
   R2025a (`CONVHULL no longer supports or requires Qhull-specific options`) — the reference used a copy with `{'Qt'}`
   dropped, and MATLAB's modern `convhull` *errors* on collinear/duplicate clouds where the port returns a degenerate
   rectangle.
9. **An eigenvector's sign is arbitrary.** `polygeom`'s `ang1`/`ang2` differ from R2025a's `eig` by exactly ±π in 13 of
   15 polygons; the *axes* are identical. The port's convention is the one reproducing the M-file's own documented
   self-test (30°/120°); R2025a running the shipped file prints −150°/120°.
10. **`load_image` must search sub-directories.** ch06 is the first chapter whose book images live inside MATLAB
    sub-folders (`Sea_Ice_Floe_Identification/`, `for test/` — with a space), and a Colab reader copies that tree
    verbatim to Drive. `resolve_case_insensitive` now tries the top level first (ch02–ch05 unchanged), then walks
    sub-directories case-insensitively in sorted order. Separately, the NASA Worldview endpoint returned a **389-byte
    blank JPEG** once for the 148×108 request; `io._fetch_non_blank` rejects a zero-variance download, deletes the
    cache entry and retries once.
11. **Rule 9 is easy to break when a new primitive lands.** ch06 wrote `core.regionprops` while ch05's
    `component_centroids` kept its own centroid code (review S8) — it is now a thin wrapper, one code path, ch05 tests
    unchanged.
12. **Docstring parity labels drift from the measurements.** Five labels contradicted the report at review time
    (`homofil` `unverified` → **exact**; `Perimeter` `near` → **exact**; `polyarea` "exact" with no reference until one
    was added; `gvf_distance`/`seaice_kmean_gvf` "exact" → **near**), plus two stale numbers embedded in comments.
    Re-read every `# PARITY:`/docstring claim against the report at the end of a chapter.
13. **A book figure may need an edge map the book never shows.** Fig. 6.16(a) is printed as a binary image; with
    `f = I` (Eq. 6.12) the GVF ring points *into* the object and no snake converges from inside. With the chapter's own
    `f = |∇I|` (Eq. 6.7, `GVF_distance.m` line 58) **both** printed claims reproduce numerically (98.6 % / 22 % / 36 %).
    Likewise Figs. 6.7/6.9 only show the traditional snake's failure at **small** σ: at the caption's σ = 4 the
    traditional snake also enters the concavity (the Gaussian is exactly what buys the capture range) — the honest
    figure is a σ sweep (0 % penetration at σ = 1, 2; 100 % at σ = 4; 100 % for GVF at any σ).
14. **`strel('disk', 3)` is 5×5 / 25 px**, not 7×7 / 37 (the analysis said 7×7 twice). It is the only printed evidence
    for `T_seed`, so the wrong number would have propagated into ch7/ch9.
15. **Test design.** The `polybool` start-vertex question was settled by *enumerating* six candidate extremal rules over
    46 clips (0 hits) rather than by inspecting one case; the sensitivity to ordering was measured by re-parameterising
    the port's **own** contour (rotate → 56–82 px, reverse → 0 px), which converts an unexplained residual into a
    bounded, explained one. Fixtures that pin an integer-class path must use an **integer** image (the M1 defect hid
    behind float64 inputs for the whole first verification round).
