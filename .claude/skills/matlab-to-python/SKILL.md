# matlab-to-python — faithful porting rules

Read `reference/function_map.md` (in this skill folder) for the function-by-function table. This file is the rules.
Also read `knowledge/function_map.md` in the repo root, which accumulates *project-verified* mappings across chapters —
it overrides this skill when they disagree.

## 1. Semantics that silently break ports
| MATLAB | Python | Rule |
|---|---|---|
| 1-based, inclusive `a:b` | 0-based, exclusive | `A(i,j)` → `A[i-1, j-1]`; `A(a:b)` → `A[a-1:b]`; `end` → `-1` / `len` |
| Column-major `A(:)`, `find`, `sub2ind` | row-major | `A.flatten(order="F")`, `np.nonzero` order differs — sort if order matters; `np.ravel_multi_index(..., order="F")` |
| `size(A)` returns rows, cols | `A.shape` | `[m,n]=size(I)` → `m, n = I.shape[:2]` |
| `zeros(n)` is n×n | `np.zeros((n, n))` | never `np.zeros(n)` for `zeros(n)` |
| `length(A)` = max dim | `max(A.shape)` | |
| `A(i,j,:) = v` **out of range grows `A`** (no error), so a result's *size* is data-dependent | numpy raises `IndexError` | a variable that starts as `[]` and is written at scattered indices ends up `max(i) × max(j) × …`, **not** the image size — reproduce the growth (track the running maxima), **never pre-allocate where the original grows**, and remember a run in which every maximum happens to be attained **cannot distinguish** the two (verified ch08: 627×1114 on the full field but 627×1096 and 489×865 on two subsets, all byte-identical). If you offer a pre-allocating override, give it its own test |
| `if x ~= NaN` (and any `if <array>`) | `if len(x) > 0` — i.e. `~isempty(x)` | a comparison with NaN is **false for every element**, so the `if` tests an empty/non-empty array, not equality; `if` on an array is "all elements non-zero", and an **empty** array is false. Published algorithms carry this: an overlap test written `[xx,yy] = polyxpoly(...); if xx ~= NaN` therefore **cannot detect containment** (a polygon strictly inside another has no boundary crossing → empty → "no overlap"). Reproduce it literally and put the corrected behaviour behind a flag; confirm all three branches (`[1 2 3]` taken, `[]` not, `[1 NaN]` taken) in MATLAB (verified ch08) |
| `if <scalar> >= <a vector that GROWS each iteration>` (`t(k) = graythresh(...)` then `if pix >= t*255`) | `all(...)` — the effective bound is the **running maximum** `max_{j<=k} t(j)` | a comparison whose right-hand side is an accumulating vector is **not** a scalar comparison: `if` means "all elements non-zero" (and an **empty** array is false). MATLAB: `uint8(50) >= [25 51]` → `[1 0]`, **not** taken; `>= [25 40]` → taken. **Read every `if` whose operand accumulates**, reproduce the running-maximum behaviour behind a flag, and choose a fixture whose threshold **falls** at some point — on a monotone series the bug is invisible (verified ch09: 17 of 24 frames change, max Δ 3.09 pp) |
| `n = n+1` where `n` is a **vector** grown by `n(k) = 0` | increment **every** element; closed form `n_final[j] = Σ_{m>=j} count_m` (a reverse cumulative sum) | the author meant `n(k) = n(k)+1`. MATLAB probe: per-frame counts (7, 6, 4) end at `n = [17 10 4]`. A quantity read **inside** the same iteration escapes this but not the running-maximum trap above — **name which of the two each reported number depends on** (verified ch09) |
| `x(k) = <call returning 0x0>` **past the end** of a growing vector | **raise** — it is not a deletion | a null assignment past the end errors, and the identifier depends on the RHS **form**: the literal `x(k) = []` is parsed as a deletion → `MATLAB:subsdeldimmismatch`; a function call returning `0x0` is an assignment → `MATLAB:matrix:singleSubscriptNumelMismatch`. Delete-and-shift only happens for `k <= numel(x)`. Make the port raise by default and put the deletion semantics behind a flag (verified ch09) |
| `np.hypot(dx, dy)` as a stand-in for `sqrt(dx.^2 + dy.^2)` | `np.sqrt(dx*dx + dy*dy)` | `hypot` is a **different, more accurate** algorithm and can differ in the last ulp — which decides the outcome when the value feeds a **strict** inequality (`if k1 < k && k < k2`). Write the literal expression; it costs nothing and removes a class of doubt (ch09) |
| a toolbox/FEX function on a **degenerate** input (1 point, 2 points, none) | probe it in MATLAB before assuming a clean return | shapes, not just values, diverge: `repmat(x,1,5)` on a 1x1 gives a **1x5 row**, so a caller's `[rectx, recty]` becomes **1x10** and MATLAB's *own* next line raises `MATLAB:badsubscript`; a 2-point branch returned a **2x1** perimeter and a 0-point branch `0x0` empties where a port returns `NaN`. If reproducing the malformed shapes would break earlier verified callers, keep the values, **document the divergence and pin MATLAB's shapes in a test** so a later silent "fix" fails (verified ch09) |
| `a:step:b` with a **non-integer** step | `core.matlab_compat.matlab_colon(a, step, b)` — **not** `np.arange` | MATLAB computes the count **once** (`floor((b−a)/step) + 1`, with a near-integer snap) and multiplies; `np.arange` accumulates and can add or drop the last element. The vector **does not reach `b`**: `0:0.05:6.28` is **126** points ending **6.25** (a "circle" drawn on it is an open polygon with a gap) and `21:79:3979` is **51** ending **3971**. Pin **both** the element count and the last value — and choose a fixture whose `(b−a)/step` is *not* integral, or the truncation logic is never exercised. MATLAB's colon is also **more accurate** than `a + k·step`: ≤ 1 ulp on 30 of 126 angles, so a port of it is `near`, not `exact` (verified ch08) |
| `jet(m)`, `hsv(m)`, … colormap tables used **numerically** (`C(index,:)` written into an image) | port the M-file (project: `core.plotting.matlab_jet`, exact for m = 1, 3, 4, 7, 30, 255) | matplotlib's `"jet"` descends from it but is a **continuous** colormap sampled at `m` points — a different table in the third decimal. R2025a's rule is `g = ceil(n/2) − (mod(m,4)==1) + (1:length(u))'`; **pre-R2014 wrote `mod(m,2)==1`**, which differs for `m ≡ 3 (mod 4)`, so test a value in that class (255) *and* one outside it (30), computing the old variant explicitly to prove the test discriminates (verified ch08) |
| `uint8` arithmetic **saturates** (200+100=255) and **rounds** (`uint8(3)/uint8(2) = 2`) | numpy **wraps** and truncates | do math in float, then push **every step** through one round-half-away-from-zero + saturate (project: `core.matlab_compat.saturate_to_class(x, dtype)`, verified ch06) — the intermediates are *not* the float64 ones. This applies **inside library/toolbox functions too**: a routine that normalises `(f − fmin)/(fmax − fmin)` evaluates it in the **input's** class, so a uint8 image comes back with only the values `{0, 1}` (ch06 `GVF.m`; ch05 `imimposemin`'s `I + h` is the same rule). Check the class of every argument a `.m` file passes down, not just the top-level one |
| `single` op `double` | numpy promotes to float64 and stays there | MATLAB **promotes to double, computes, and rounds the result to single ONCE**. Pinned on 540 radii `single(D)/sqrt(2)`: promote-round-once **540/540** bit-exact, rounding the double operand to single first **360/540** (≤ 1.91e-6 off), pure float64 **6/540** (≤ 7.67e-7) — so neither a naive float32 port nor a float64 one is right (verified ch06). It matters whenever a discontinuous function (`ceil`, `round`, `>`) consumes the value. `bwdist`, `graythresh`'s internals and `imresize` all return `single` |
| `round` = half away from zero | numpy = banker's | use `np.floor(x + 0.5)` (positive) or `np.sign(x)*np.floor(abs(x)+0.5)` when matching matters |
| `A'` conjugate transpose | `A.T` | `.T` for real arrays |
| `.*`, `./`, `.^` elementwise; `*` matmul | `*`, `/`, `**` elementwise; `@` matmul | |
| `&`/`|` elementwise, `&&`/`||` short-circuit | `&`/`|` arrays, `and`/`or` scalars | |
| `mod(a,b)` sign of b; `rem` sign of a | `np.mod` = MATLAB `mod`; `np.fmod` = `rem` | |
| `im2double` on uint8 = /255 | `skimage.util.img_as_float` | `im2uint8` = `img_as_ubyte` (rounds ×255) |
| `uint8(x)` **cast** (values already 0–255) ≠ `im2uint8(x)` (×255 first) | `np.clip(np.floor(x+0.5), 0, 255).astype(np.uint8)` (project: `core.matlab_compat.to_uint8_saturating`) | the cast rounds half-away-from-zero and saturates; `x.astype(np.uint8)` wraps *and* truncates — never use it for a MATLAB cast (verified ch02) |
| `imhist(BW)` on a **logical** image → 2 bins at [0, 1] | `np.bincount(BW.ravel(), minlength=2)` (project: `core.histogram.imhist`) | `imhist(I, n)` bins by `round(v·(n−1)/top)`, floats clipped to [0,1]; uint8 default 256 (verified ch02) |
| `imshow(I,[])` scales | `plt.imshow(I, cmap="gray")` (auto-scales) | `imshow(I)` uint8 → `vmin=0, vmax=255` |
| `imread` JPEG | `imageio.v3.imread` / `skimage.io.imread` | both give HxWx3 uint8 RGB — same decoder differences possible (libjpeg versions): compare with a tolerance of ±1 gray level for parity tests on JPEGs |
| `rgb2gray` (Rec.601: 0.2989 0.5870 0.1140, uint8 rounded) | `skimage.color.rgb2gray` uses **Rec.709** (0.2125 0.7154 0.0721) | write `core/matlab_compat.rgb2gray_matlab` |
| `imfilter(I,h)` = **correlation**, zero padding, 'same' | `scipy.ndimage.correlate(I, h, mode="constant")` | `imfilter(...,'conv')` or `conv2(...,'same')` → `scipy.signal.convolve2d(I, h, mode="same", boundary="fill")`; `'replicate'` → `mode="nearest"`; `'symmetric'` → `mode="reflect"`. MATLAB passes these as **positional strings in any order** (`imfilter(I,h,'replicate')`): give the Python wrapper `*options` so a mechanical port cannot misassign them to a `mode` argument (project: `core.filters.imfilter`, verified ch02). A book may print a "convolution" equation in correlation form — check which call the `.m` file uses before labelling parity |
| `medfilt2` zero-pads | `scipy.ndimage.median_filter(mode="constant", cval=0)` | scipy default is `reflect` = MATLAB's `medfilt2(..., 'symmetric')` option (verified ch04) |
| `double(im)/256` in a script vs `im2double(im)` (/255) | port the literal division (`im.astype(float)/256`) | authors often write `/256`; every threshold quoted for that script (`edge(im,'sobel',0.05)`) refers to that scaling, and MATLAB's automatic thresholds change with `/255`. Never "fix" it to `im2double`; make the edge function refuse integer input so the scaling is always explicit (verified ch04) |
| `strel('disk',r)` (default n=4 → *approximate*, decomposed disk) | port MATLAB's periodic-line decomposition (project: `core.morphology.strel`, exact, verified ch04); `skimage.morphology.disk(r)` / `cv2.getStructuringElement(MORPH_ELLIPSE)` are *Euclidean* disks — a different shape | MATLAB's default disk is an **octagon** (Adams 1993: `v = [1 0; 1 1; 0 1; −1 1]`, `k = 2r/(cot(π/2n) + 1/sin(π/2n))`, `rp_q = floor(k/‖v_q‖)`, periodic lines dilated together, then horizontal/vertical lines of length `2(r − max_horiz_radius − 1) + 1` if ≥ 3): r = 5 → 9×9/69 px (a Euclidean disk is 11×11/81), r = 7 → 13×13/157. `r < 3` or `n = 0` → exact `x²+y² ≤ r²`. `strel` (like every `validatestring` function) accepts **unambiguous prefixes**: `strel('dis', 7)` is `'disk'`, `'di'` errors. Origin = `floor((size+1)/2)` also for even SEs. Eroding/dilating with the decomposed sequence equals the flat neighbourhood (Minkowski sum) and is much faster on large images |
| `imerode(I,se)` / `imdilate(I,se)` border and reflection | `cv2.erode/dilate(..., borderType=BORDER_CONSTANT, borderValue=…)` with an explicit pad value and a **flipped kernel + remapped anchor** for dilation (project: `core.morphology.imerode/imdilate`, exact, verified ch04) | erosion pads with 1 / intmax / +Inf, dilation with 0 / intmin / −Inf, and dilation uses the **reflected** SE (Eqs. `A ⊕ B = {z | (B̂)_z ∩ A ≠ ∅}`, `max f(x−s, y−t)`) — invisible for symmetric disks, decisive for asymmetric/even SEs; OpenCV and `scipy.ndimage.grey_*` differ in the reflection convention, so pin it with an asymmetric-SE reference. **`scipy.ndimage.minimum_filter/maximum_filter` route `cval` and the accumulation through float64** → wrong for int64/uint64 (intmax pad overflows to intmin; values > 2⁵³ corrupted): pad with numpy in the native dtype and shift-and-reduce. **MATLAB itself rejects int64/uint64 images** in `imerode`/`imdilate` (accepts single/double/int8/16/32/uint8/16/32/logical) → those dtypes can only be verified at L1; cast `skimage.measure.label` (int64) output to int32 before any MATLAB comparison |
| `imclose(I,se)` ≠ `imerode(imdilate(I,se),se)`; `imopen` = bare composition | reproduce MATLAB's pre-pad (project: `core.morphology.imclose`, exact, verified ch04); `skimage.morphology.closing` is the bare composition → `near` at the border | R2025a `imclose.m` pre-pads `padarray(A, ceil(size(getnhood(se))/2), 'both')` with **0**, dilates, erodes, crops (dark notches open to the image border are not closed); `private/morphop_fast.m` sends SEs with nnz < 600 ∧ every side ≤ 15 ∧ not an all-ones rectangle to a Halide kernel whose pad is the **class minimum** (−Inf/intmin/false; setting `images.UseHalide`, default on). Both coincide for uint8/logical/non-negative double and differ only for signed images with negative values. `imopen.m` applies `imdilate(imerode(A))` unpadded. 43 of 54 closings were wrong before this was reproduced |
| `bwdist(BW)` distance to nearest **nonzero** | `scipy.ndimage.distance_transform_edt(~BW)` | note the complement! `cityblock` → `distance_transform_cdt(~BW, metric="taxicab")`, `chessboard` → `metric="chessboard"`, `quasi-euclidean` → re-implement (two-pass chamfer 1, √2; exact in float64 while MATLAB's single-precision result is ~1e-4 off). MATLAB returns **single** → compare with `atol≈1e-4` (verified ch02, project `core.distance.bwdist`). **Keep the float32 array** when the distance map feeds `imregionalmin`/`imimposemin`/`watershed`: the regional-minima ties and flooding priorities must match bit for bit, and a float64 recomputation shifts Euclidean/quasi values by ~1e-6 (verified ch05) |
| `bwlabel(BW)` default 8-conn | `skimage.measure.label(BW, connectivity=2)` | `bwlabel(BW,4)` → `connectivity=1`. MATLAB numbers labels in **column-major order of first occurrence**; relabel skimage's output that way when code indexes cells/`regionprops` by label number (project: `core.connectivity.label_components`, exact incl. numbering, verified ch02) |
| `watershed(A[, conn])` 8-conn, 0 on ridge lines | port R2025a `toolbox/images/images/eml/watershed.m` line by line (project: `core.watershed.watershed`, exact incl. label values, verified ch05); `skimage.segmentation.watershed(A, connectivity=2, watershed_line=True)` is only `approx` | The interpreted `watershed.m` calls a compiled builtin, but its **codegen twin `eml/watershed.m`** is readable Meyer flooding: seeds `bwlabel(imregionalmin(A, conn), conn)`, `FifoPriorityQueue` = a min-heap on `(priority, insertion order)` (`heapq` on that tuple is identical), an **initial push scan in column-major order** (order-sensitive — transposing the image changes 31 of 80 cases; the neighbour order inside the loop is provably irrelevant), a popped pixel that sees two labels stays 0 **and pushes nothing**, each pixel pushed once with priority `max(A(nb), p)`. skimage seeds with the minima pixels, re-pushes, tags entries with a source label, keeps propagating from line pixels and orders neighbours by distance → ridges differ (46–122 px on a 96×81 image) and even the basin partition disagrees — unusable where the ridge pixels are consumed downstream. MATLAB **rejects int16/int32** input (uint8/uint16/single/double/logical only) and returns uint8/uint16/… by region count (cast to int32 before comparing); 3×3 `conn` matrices only as the cross or `ones(3)`. Ridges are 4-connected staircases on distance maps but **thick on plateaus** (gradient/gray images) — MATLAB identical. Pure-Python heap ≈ 3 s per Mpx |
| `regionprops(L, 'Area','Centroid','BoundingBox','ConvexHull','ConvexImage','ConvexArea','Solidity','Major/MinorAxisLength','Eccentricity','Orientation','Perimeter')` | **re-implement from R2025a `regionprops.m`** (project: `core.regionprops.regionprops`, exact ≤ 1.07e-14 on 40 shapes × 10 properties and on 344 real components, verified ch06); `skimage.measure.regionprops` is a **different algorithm** | skimage's `axis_major_length` (10.2935 vs MATLAB 10.3581), `perimeter` (26.83 vs 25.42, +5.5 %) and `orientation` (+90°, radians) are close enough to look right and wrong enough to move a threshold decision (`Solidity < 0.9`, `major/minor > 2`). MATLAB's rules: normalised second central moments **+ 1/12**, `y` negated, `uyy > uxx` branch, degrees; `Centroid` = 1-based `(x, y)` in `bwlabel` order (`floor` gives a one-pixel marker); `BoundingBox` `[x y w h]` with 0.5 offsets; `ConvexHull` = hull of the **mid-edge points** of the `bwmorph('perim8')` pixels via `convhull(rr, cc)` (that argument order); `ConvexImage` = `roipoly(M, N, c, r)` with the `firstRow/firstCol` shift; `Perimeter` = Vossepoel–Smeulders `0.980·even + 1.406·odd − 0.091·corners` over the 8-connected closed boundary. Support **both call forms** — a label matrix and the common `regionprops(L == n, …)` loop |
| `imresize` bicubic (Keys a=−0.5, antialias when shrinking) | cv2 bicubic a=−0.75; skimage order=3 = B-spline | for Ch2 §2.8 **implement the kernels from the book's equations**; never claim exact parity with library resize |
| `[level, em] = graythresh(I)` = `im2uint8` → `imhist(256)` → `otsuthresh`, level∈[0,1], `em` = separability η(t*) | port `otsuthresh` (project: `core.threshold.graythresh`, exact, verified ch03); **not** `skimage.filters.threshold_otsu` | MATLAB **averages tied maximisers** (`mean(find(σB² == max))`), so `255·level` can be a half-integer — keep it float. `im2bw(I, level)` = `I > 255·level` (strict >, compared in **double**: `uint8 > 104.5` works); `im2bw` converts RGB with `rgb2gray`, `graythresh` does **not** (it histograms all planes) — so `im2bw(rgb, graythresh(rgb))` and `im2bw(gray, graythresh(gray))` are **different masks** (130/255 vs 128/255 on a 96×81 toy image, verified ch05); port whichever the script writes, never "normalise" to gray |
| `[thresh, metric] = multithresh(I, N)` | port R2025a `multithresh.m` (project: `core.threshold.multithresh`, exact N ≤ 2, verified ch03); `skimage.filters.threshold_multiotsu` is `approx` | `getpdf` normalises in **single** and the `grayto8` builtin multiplies by 255 in single too — a float64 product moves a bin edge; output thresholds come back in the **input class**; N ≥ 3 uses `fminsearch` (local; can return its initial guess with `metric = −Inf`) → an exhaustive port is `reimplemented`, never `exact`; degenerate inputs (`numel(unique(A)) ≤ N`) use `getDegenerateThresholds`. `imquantize(A, t)` = `1 + Σ(A > t_i)` |
| `histeq` default 64 bins | `skimage.exposure.equalize_hist` (256) | `approx` unless re-implemented |
| `kmeans` (Statistics Toolbox: k-means++ init, random) | `sklearn.cluster.KMeans(n_clusters=k, n_init=10, random_state=0)` | never expect identical labels; compare cluster *centers* sorted, and pixel agreement ≥ 99%. **First check whether the chapter folder ships its own `kmeans.m`** — a script named like a toolbox function *shadows* it (the book's `ch3/kmeans.m` is a deterministic histogram k-means with equal-division init, ported exactly as `core.clustering.kmeans_gray`, verified ch03); never `addpath` such folders when generating references |
| `num2str(x)` (scalar, default format) | integers → `str(int(x))`; else `f"{x:.{n}g}"` with `n = max(floor(log10|x|) + 5, 5)` (project: `ch03_ice_pixel_detection._num2str`, verified ch03) | 4 significant digits after the leading ones: `73.8472`, `86.496`, `0.12346`, `1234.5679` — needed for byte-identical figure titles |
| `sum(x)` on integer vectors; loop buffers `s(j) = I(p(j))` | `np.sum(x, dtype=np.float64)`; emulate stale entries explicitly | integer `sum` accumulates in **double** (no saturation); an array grown inside a loop is never cleared, so a smaller later class reuses stale entries (verified ch03: the authors' "mean intensity" of 4759.10) — reproduce behind a flag, never silently |
| `[BW, t, gv, gh] = edge(I,'sobel'\|'prewitt', T, dir, 'thinning')` thresholds & **thins** | re-implement (project: `core.edges.edge`, exact — 252 maps 0 px vs R2025a, verified ch04); `skimage.filters.sobel` gives a magnitude only | `op = fspecial('sobel')/8` (Prewitt `/6`, applied **after** filtering with the integer kernel — folding `/6` into the kernel costs 1 ulp), `bx = imfilter(a, op', 'replicate')`, `by = imfilter(a, op, 'replicate')`, `b = kx·bx² + ky·by²` (`kx, ky` = 1,1 / 0,1 `'horizontal'` / 1,0 `'vertical'`), `cutoff = T²` or `4·mean(b)` (returned `t = sqrt`), `'nothinning'` → `b > cutoff`. Thinning (compiled `computeEdges`): with `bx = |bx|`, `by = |by|` and `b` **zero-padded** by 1 px, `e = b > cutoff & ((bx >= kx·by − 100eps & b(r,c−1) <= b(r,c) & b(r,c) > b(r,c+1)) \| (by >= ky·bx − 100eps & b(r−1,c) <= b(r,c) & b(r,c) > b(r+1,c)))` — the dominance multipliers sit on the *other* component, ties keep the first pixel (`<=` left/up, strict `>` right/down); replicate-padding `b` differs at the right/bottom border. Roberts: masks `[1 0; 0 −1]/2`, `[0 1; −1 0]/2`, auto scale 6, thinning offsets `[−1 1 1 −1]`. Pin the rule with **constructed-tie fixtures** (a random field or a real image can match by luck) |
| `edge(I,'log', T, σ)`, `edge(I,'zerocross', T, H)` | re-implement the readable M-code branch (project: `core.edges.edge(..., 'log')`, exact on images, verified ch04) | `fspecial('log', 2·ceil(3σ)+1, σ)`, `op −= mean(op)`, replicate `imfilter`; an edge is the **negative** side of a sign change with its right/lower (or left/upper) neighbour whose **jump** `\|b(p) − b(q)\| > T` (`2T` at exact zeros), interior only; auto `T = 0.75·mean\|b\|`. On piecewise-constant inputs the strict `> 0` tests act on ~1e-17 rounding noise whose sign differs between MATLAB's `imfilter` and scipy → `near` there, exact on real images |
| `edge(I,'canny')` sigma=√2, hysteresis thresholds auto | `skimage.feature.canny(sigma=np.sqrt(2))` | `approx` |
| `fspecial('log'/'gaussian'/'laplacian'/'average'/'disk'/'sobel'/'prewitt'/'unsharp')` | port `fspecial.m` (project: `core.filters.fspecial`, exact ≤ 7e-18 for 26 kernels, verified ch04) | gaussian: `exp(−(x²+y²)/2σ²)`, entries `< eps·max` zeroed, unit sum, defaults 3×3/σ 0.5, only-σ → `2·ceil(2σ)+1`; **log**: unit-sum Gaussian × `(x²+y²−2σ²)/σ⁴` then **mean-subtracted** (sum 0) — *not* the textbook `∇²G` sampled (which carries `1/(2πσ⁶)` and does not sum to zero; a book's printed LoG kernel is usually `fspecial`'s), default 5×5/σ 0.5; laplacian `[α 1−α α; 1−α −4 1−α; α 1−α α]/(α+1)`, α 0.2; average `ones/prod`; disk area-weighted pillbox r 5; unsharp `I − laplacian(α)`. Prefixes accepted |

## 2. Porting procedure for one `.m` file
0. If a toolbox call is a **compiled builtin** (`images.internal.builtins.*`), look for its readable **codegen twin**
   `toolbox/images/images/eml/<name>.m` (+ `+images/+internal/+coder/*` helpers such as `FifoPriorityQueue.m`,
   `NeighborhoodProcessor.m`) before reverse-engineering: the twin is plain M-code meant to produce identical results
   and can be ported line by line (ch05 `watershed`: 0 px on 74 constructed cases). Only when there is no twin (ch04
   `computeEdges`) reverse-engineer from constructed-tie fixtures. Either way, pin scan/queue **order** with fixtures
   that a different order would change (corridors, asymmetric adjacency and its transpose, odd/even plateaus).
1. Read the whole file; list every toolbox call; decide per call: library (which, which args) / `core/` primitive / re-implement.
2. Write the Python version preserving the *structure* (same variable names where sensible, same step order) so the verifier can line them up.
3. Where MATLAB scripts `imshow` intermediate results, the Python script saves them to `outputs/chNN/` with descriptive names and returns arrays.
4. Put every numeric constant that came from the book in a named variable with a comment citing the equation/figure.
5. Add a `# PARITY:` comment at each non-exact substitution.
6. Track the **class** of every value through the call chain (`uint8` → `double` only where MATLAB actually converts) and
   the class of every result MATLAB stores (`single` from `bwdist`/`imresize`). Class errors are invisible until a
   discontinuous consumer (`ceil`, `>`, `round`) amplifies them; they are also what makes a library function behave
   differently on the same numbers (ch06 §1 rows 1–2).
7. When a routine's source is unavailable and its *output ordering* is not reproducible, define the contract in terms of
   sets/masks, and **measure the sensitivity** by re-parameterising your own output — that converts an unexplained
   residual into a bounded, explained one.
8. Before closing the chapter, re-read every docstring parity label and every number embedded in a comment against the
   verification report: they drift (ch06 review found five wrong labels and two stale numbers).  This includes **retracted** claims that
   survive in a *neighbouring* module's docstring (ch09: a corrected MATLAB error semantics was still asserted in the
   fixture generator).
9. **Port dead code as dead.** A shipped file can carry validation that can never run — `if (nargin<3)` inside a
   **two-argument** function makes the whole `elseif` unreachable, so MATLAB silently accepts *every* value of that
   argument (`''`, `[]`, `'x'`, a number, a string — all identical). Reproduce the reachable behaviour, honour the
   `isempty` half of such a guard (an empty argument is the **default**, not an error), and record any stricter
   validation you add as a deviation.
10. **Generate the patch record, never hand-write it.** Emit it from the same dictionaries that drive the patching and
   assert in a test that every recorded `removed` line is **byte-identical to the shipped line it claims to replace** —
   a hand-written record drifts (it omitted appended lines that a test was already consuming, and misrecorded a kept
   line as deleted).

## 3. Things that are not bugs
- Different label numbers, different cluster indices, JPEG decoder ±1 level differences, Otsu threshold ±1 level on 256 bins,
  float32 vs float64 noise ~1e-6. Handle with the right comparator (see `tools/compare_arrays.py`), not by hacking the algorithm.
  (But when the port claims `exact` for `bwlabel`/`watershed`, compare the **label values** — MATLAB's numbering is
  reproducible and a partition-only comparison hides ordering bugs.)
- Label-image **classes** (MATLAB uint8/uint16/double by region count vs int32 here), `label2rgb(...,'shuffle')` colours
  (private fixed-seed stream), `imshow(I, [])` PNGs off by one level at exact half-integers of the `mat2gray` stretch,
  `imcontour`/`surf` rendering details — display-only; the arrays underneath must still be exact.
- **Two different minima of a flat objective.** If a parameter is *unidentifiable* — the truncated power law
  `ε₁(L^{-ε₂} − ε₃^{-ε₂})` degenerates to the plain power law as `ε₃ → ∞` — the objective is flat along it and
  "parity" in that direction is meaningless: two solvers legitimately land 3 orders of magnitude apart (766 vs
  9.94e5) and the *newer* one can be the better fit (smaller residual in 2 of 3 fixtures). **Measure the
  objective, not the parameter**, report both minima, and prove the flatness with a refit test (fix the
  parameter anywhere across the range, refit the others, show the residual moves by < tol) — ch08.
- Thick watershed ridges on plateaus (gray or gradient segmentation functions): MATLAB's Meyer flooding produces them too;
  a book's "1-pixel-thick line" claim only holds on distance maps.

## 5. Test-design lessons
- **A test on a convex blob cannot exercise "spurious watershed line removed"**: its distance transform has a single
  regional minimum, so there are no lines and `all([])` passes vacuously. Use a peanut (two overlapping discs) for the
  removal branch and a fixture whose 4- and 8-connectivity results differ to pin the default `conn` (ch05 review).
- Fixtures with more than 255 regions exercise MATLAB's uint16 label class; `±Inf` plants exercise the `h = Inf` path of
  `imimposemin`; constant and all-`±Inf` images exercise the regional-extrema special case.
- Wrap every MATLAB probe in `try/catch` and store the error text — a rejected class (`int16` for `watershed`, `int64` for
  `imerode`) is evidence, not a failed run; reference those fixtures on `double(X)` and say so.
- A shipped `.fig` is a MAT v5 file: `openfig(f, 'invisible')` + `get(findobj(...))` gives the authors' own image `CData`
  and plotted points — a free L3 truth (ch05 Fig. 5.14(f)).
- **An integer-class code path needs an integer fixture.** A branch fed only float64 inputs hid a real defect (MATLAB
  binarising an edge map in uint8) through a whole verification round; the branch "had a test" and the test proved
  nothing (ch06 must-fix M1). List the *branches* of each ported function, not just its files, and give each one a
  reference — including the branches the shipped drivers never take.
- **Settle an ordering hypothesis by enumeration, not by inspection**: check every candidate rule (max-y, min-y, max-x,
  min-x, both lexicographic extremes) over *all* available cases; "0 of 46" is a result, one matching example is not.
- Run the original `.m` from a scratch copy under a **non-shadowing name** — a script named like a toolbox function
  (`dist.m`, `kmeans.m`) silently shadows it and changes what the reference measures.
- A book figure may require an input the book never prints (an edge map rather than the binary image), and a caption's
  parameter value can hide the very effect the figure claims (a Gaussian σ large enough to fix the failure being
  illustrated). Sweep the parameter, print the sweep, and say which value the figure used.
- **A test whose fixtures cannot distinguish the fix from the bug is not a test.** An `eps(edges)` vs `nextafter(edges)`
  fix would have survived a revert with the whole suite green, because none of the 16 committed fixtures had an internal
  edge at a negative power of two. The discriminating case has to be *constructed*, and the test should compute the
  **wrong** variant explicitly and assert it differs — that is the only proof the fixture discriminates. Pin a fixed
  defect in **both** directions: monkey-patch the old expression back in and assert it fails against the reference (ch07).
- **Choose fixture *shapes* that can fail, and prove it by introducing the bug.** A **square** fixture cannot
  catch a `(row, col)` ↔ `(x, y)` transposition (`NumPix_x = size(I, 2)`): swapping the two names left all four
  fixtures and every assertion green. A field in which **both pixel maxima are attained** cannot distinguish a
  grown array from a pre-allocated one. Both were fixed by changing the fixture, not the assertion — one image
  is now 80×137 and two new subsets reach neither the last row nor the last column — and the discrimination was
  **demonstrated**: the swap was applied to the real module, observed to fail on the non-square fixture only
  (`PixScale_x` 0.625 vs 0.36496350364963503), and reverted with the file's md5 unchanged (ch08).
- **Reach for the authors' own deterministic routine over a library equivalent with an RNG when both exist.**
  A chapter whose text says "the k-means method" means the book's own `kmeans.m` (ported `exact`, no seed), not
  the toolbox routine approximated by a seeded Lloyd/k-means++ (`approx`, and seeds 0/1/7 gave three different
  centre triplets). Using the RNG routine where the deterministic one applies is a silent parity downgrade;
  keep the seeded path behind an explicit opt-in and pin **both** branches with numbers that differ, so a test
  in which the switch silently routed both to the same code would fail (ch08 review).
- **Rank the evidence: a shipped `.mat` of the authors' *own results* beats every fixture you can build.** Where
  one exists, re-run their code on their own stored inputs and compare **structure to structure**, not just
  array to array (ch08 reproduced 2888 floes + 3452 brash including all 3992 overlap-list entries, hull vertex
  sets 2888/2888 and a byte-identical painted map). Same family as the shipped `.fig` above.
- **Beware a numeric agreement that a saturating function — or a constants-only formula — makes inevitable.** Colour-bar tick lists matched a book
  figure exactly — but the mapping `fix(10⁴(1 − e^{−A/10³}))` is 9997 for *every* `A ≥ 8112`, so any run with the same
  smallest object prints that list (two runs identifying 319 and 393 objects both matched). Before recording an exact
  match as parity, **ask what fraction of the input space would produce it**; enumerate the pre-image of the printed
  values and report the band (ch07: 4 of 11 lists were unbounded, 7 pinned the largest area to within 1–19 px;
  ch08: a nine-integer tick list that depends on **three literals only** was
  explicitly disqualified as parity evidence by a test feeding it three wildly different inputs). **The same
  trap in reverse: an agreement a *degenerate fixture* forces is not evidence** — a claimed "k = 2 k-means ≈
  Otsu" equivalence was 100 % true on a two-tone image whose histogram has a 150-level empty band, where *every*
  threshold in the band gives the same mask. Rebuilt on a ramp covering every level, the two thresholds differ
  (116 vs 116.2525), the masks still agree 100 %, and 11/30 pixels sit at the two decisive levels — so a
  one-level move would break it. That is a result; the first version was an artefact (ch08).
- **A cited measurement must name its input.** "1232 pieces / 433 floes / 290 brash" came from the port's own upstream
  stage; the reference stage gives 1211 / 433 / 274. Both are true, only one is a parity number, and a report that
  mixes them cannot be audited. Write the input beside every number (ch07). **It recurs at every boundary between a verified stage and
  its consumer**: an `exact` label measured on *MATLAB's own* intermediate array is not the end-to-end result — feeding
  the port's own upstream output (0.2 % different) moved an overlap-flag count 34 → 36 and a derived concentration by
  0.104 pp. State both, and add **ceiling assertions** for the end-to-end numbers so a regression cannot hide behind
  count-only checks (ch09).
- **Duplicated code across folders does not mean duplicated data.** Two chapter folders held 23 byte-identical `.m`
  files but re-encoded copies of the same JPEG (84 % of samples differ, max 43): the same Otsu level, but 215 vs 231
  labelled components, and a stage previously measured at 0 px now differing on 0.125 %. Diff the **data** as well as
  the code before inheriting any earlier number, and make the loader resolve to the current chapter's own copy (ch07).
- **When two definitions coincide on your fixture, you have not discriminated them.** A report claimed an arithmetic
  agreement *proved* which of two definitions a caption meant — but on six **equal** blocks the two are algebraically
  identical (`Σ num/(r·c) ≡ mean(ic_b)`, measured equal to the last bit), so the fixture forced the match. The claim was
  downgraded to "consistent with, cannot discriminate", and the only real evidence turned out to be a *deleted line* in
  the script. Before writing "proves", construct the input on which the two candidates differ — and if none exists,
  say so (ch09; same family as the degenerate-fixture and saturating-agreement traps above).
- **A known-answer assertion must be chosen so the *wrong* implementations fail it.** `29/9` as the aspect ratio of an
  **axis-aligned** rectangle does not discriminate a minimum-area-rectangle rule from a bounding-box rule — they agree
  there. A **45°-rotated** rectangle does (min-rect **4.0** vs bbox **1.0**). Compute the wrong rules inside the test and
  assert they differ; a test that only asserts "the two options disagree" pins neither (ch09).
- **`reimplemented` requires a reference or a known answer; a no-reference wiring is `unverified`.** Two carefully
  written, documented functions for book text with **no shipped `.m` and no stated grid/overlap/stitch rule** were
  relabelled `unverified`, given a `# DEVIATION` marker, kept out of every parity assertion and given their own open
  item. Do not inflate a label for effort (ch09).
- **An integer- or single-class branch of a *library* function needs a fixture in that class** — the two must-fix
  defects of this project (ch06 `GVF` on uint8, ch07 `imcomplement` on `single`) both hid behind float64 inputs for a
  whole verification round, and both were latent in the chapter that introduced them and fatal in the next one.

## 4. Host / tooling pitfalls (Windows + Anaconda + venv)
- **Headless notebook runs use the wrong interpreter unless the venv is first on `PATH`**: the `python3` kernelspec that
  `jupyter nbconvert --execute` resolves is Anaconda's base python, not `.venv`, even when nbconvert itself is launched as
  `.venv/Scripts/python.exe -m nbconvert`. Prepend `.venv/Scripts` to `PATH` (or register a dedicated kernelspec pointing at
  the venv) before executing; otherwise imports fail or silently run against different numpy/scipy versions (ch04).
  Use `python -m nbconvert` rather than `python -m jupyter nbconvert` (the latter may dispatch to Anaconda's binary).
- Quote every path (repository roots with spaces); `PYTHONIOENCODING=utf-8` for non-ASCII prints on a cp1252 console.
- **Bash heredocs on this host unescape `\n` / `\\`** inside `<<'EOF'` blocks handed to the Bash tool: a Python patch script
  containing backslashes (regexes, `"\n"` literals) gets mangled. Write such scripts with the Write/Edit tools (or to a
  file first) and run the file (ch04 verifier).
- **Orphaned MATLAB processes slow everything down**: each `matlab -batch` launch spawns `MATLABWindow` helpers that can
  outlive a timed-out run; seven of them made `import scipy` take minutes and a 7-min pytest run take 69 min (ch04).
  Before a long test/reference run: `tasklist | findstr -i matlab` and end stale ones from *our* runs (`taskkill /PID …`);
  `tools/run_matlab_ref.py` now accepts a complete `.mat` even when `matlab.exe` fails to exit within the timeout.
- Reference generation: never run MATLAB from the read-only source folder — copy scripts verbatim into a scratch cwd under a
  non-shadowing name, patch only literals, never `addpath` a folder that ships a file named like a toolbox function.
